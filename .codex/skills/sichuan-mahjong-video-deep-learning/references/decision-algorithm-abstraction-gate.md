# 决策算法抽象与反过拟合门禁

## 目标

视频是策略证据，不是运行时牌谱。正式 AI 应学习“在什么公开状态下，如何估计、比较和切换路线”，不能学习“本局先打九、再打七，所以见到九后七就压低六”之类动作暗号。

每条视频必须经过三层分离：

1. **事实层**：原片当时可见的手牌、定缺、弃牌、副露、巡数、合法动作与老师原话。
2. **原则层**：隐藏状态假设如何随公开证据更新，候选路线按哪些状态变量、约束和目标比较。
3. **算法层**：对任意花色、点数和座位都适用的输入、状态转移、目标函数与输出；视频中的具体牌张仅作为测试夹具。

事实层可保留完整时序用于解释和训练数据标注，但不得直接成为生产候选牌乘数、视频专属 if/else、固定动作序列识别器或单局权重来源。

## 必答的算法问题

每个知识单元都要回答：

- `algorithmic_question`：AI 真正要解的通用决策问题是什么；
- `state_variables`：当时可公开计算的状态量，如期望可达活张、竞争度、威胁强度、剩余巡数、动作后结构、番值、尾部损失；
- `action_space`：比较哪些合法动作或路线；
- `objective_terms`：优化什么，例如净分期望、逃跑速度、和牌可达性、尾部风险；
- `invariants`：换花色、换座位或改牌面名称后仍应成立的性质；
- `reversal_conditions`：哪些状态变化必须使选择减弱或翻转。

不能把“老师这局打了某张”写成算法问题，也不能把具体牌名、视频 ID 或结局写成不变量。

## 生产实现允许与禁止

允许进入正式 AI 的实现包括：

- 基于公开状态的牌墙/对手范围后验；
- 对任意候选路线计算实际可达活张、竞争、动作后结构和剩余时间；
- 威胁调整后的条件期望、尾部损失、停止线和动态路线切换；
- 四川规则合法性、计分和状态转移；
- 使用多来源数据校准、且有独立留出验证的参数。

禁止直接进入正式 AI 的实现包括：

- 识别单条视频中的固定摸打、碰后弃牌或相邻牌顺序并给牌张加减分；
- 在生产代码中硬编码视频 ID、老师名、某一局的具体牌列或结局；
- 由单条视频生成数值权重、概率或阈值；
- 用未来摸牌、牌墙顺序、摊牌暗手或最终输赢解释事前决策；
- 仅把既有组件路径写进报告，却没有证明该节点真的改变或验证了通用算法行为。

若视频只提供一个已有算法的解释案例，而没有带来新算法，也可以合格：报告应写为 `validated_existing_algorithm`，并用该视频节点和跨牌例测试证明现有算法已覆盖。不得为了“一视频一改动”制造新权重。

## 四类强制泛化验证

AI 应用报告必须引用真实可执行证据，至少覆盖：

1. `suit_rotation`：条、筒、万结构等价时，算法输出按花色置换保持等价；
2. `structural_variant`：改变具体点数/牌名但保留状态变量关系，仍复现同一原则；
3. `broken_assumption`：破坏关键前提后，原选择减弱或翻转；
4. `outcome_invariance`：只替换未来牌墙、摊牌或结局，事前公开输入相同，决策不变。

测试不得只断言说明文字、字段存在或某个视频原局选中了同一张。至少一项测试必须通过正式 C# 决策入口，证明算法实际参与候选排序或动作选择。

## 数值参数门禁

`calibration`必须说明：

- `video_derived_numeric_weights`固定为`false`；
- 无新增数值参数时写`mode: qualitative_or_existing_calibration`；
- 有新增参数时写`mode: multi_source_calibrated`，列出独立牌谱/仿真来源、训练与留出划分、对照基线和晋级结论。

单视频只能提出参数方向假设，不能决定参数值。

## 历史复审

Skill 或本门禁升级后，所有此前声称`implemented_and_verified`的包都要重新审计：

1. 原片哈希一致时复用媒体、帧、OCR和已经通过的事实/语义证据；
2. 将旧 AI 报告降为待复审，逐节点填写算法抽象、反过拟合检查与四类泛化验证；
3. 搜索生产代码中的视频特定序列、牌名乘数和单局权重，删除或提升为通用状态算法；
4. 重新运行当前验证器与聚焦 C# runtime 测试；
5. 只有新版`algorithm_abstraction_gate=true`后才能恢复 AI 应用完成状态。

复审不能批量改字段冒充通过。共享算法可以被多个视频共同验证，但每条视频仍需逐节点说明它验证了算法的哪一部分及边界。
