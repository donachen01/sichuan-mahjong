# 核心观点提炼与 AI 转化方法

## 主次关系

单条视频的首要任务是学会潇老师在教的决策方法。识别原片、图像、牌面、动作和字幕只是为这个目标提供可追溯证据。若本轮处于知识采集阶段，先形成可靠学习笔记和能力草案，不要求同步转成四川麻将 AI；进入机制与验证阶段后，才把多来源知识正确转成共享算法。不得因为全片已播放、OCR 已生成、联系表已看完或某个字段验证通过，就宣称“已学会”。

## 视频学习技巧

1. **先复用并校验本地原片。** 以视频 ID、标题、时长和 SHA-256 锁定原片。本地精确来源可用时不重新下载，不用相似视频替代。
2. **第一遍看全局因果链。** 从 00:00 开始用 1 FPS 基线、联系表和完整播放记录客观时间线，先分清座位、定缺、副露、弃牌顺序、摸切/手切、杠胡与分数变化，不急于写策略结论。
3. **第二遍只围绕决策转折点回看。** 找出博主开始比较候选、改变攻守模式、修正对手范围或明确“不能这样打”的窗口。扩大该窗口前后时间，必要时用 2 FPS 或精确时间戳补帧。
4. **字幕与牌面双向校验。** OCR 只是候选文本；同音牌名、点数、座位和否定词必须回原帧核对。人工视觉复核时应保存转写区间和证据帧，不得伪称自动 OCR 已识别。
5. **不只记动作，要记动作前的信息更新。** 对每个关键点写“新公开证据→哪些候选结构升权/降权→哪个收益或风险发生变化→为何转换动作”。对手不碰/不杠/不胡、手切与弃牌先后只能作为通用行为似然，不能当作暗手定论。
6. **用同片内的多局对照找不变项。** 若视频含两局或多个类似节点，比较它们共同的触发条件、状态更新与翻转条件。重复出现的方法比某一手的具体摸打更接近核心观点。
7. **结局隔离。** 和牌、点炮、亮手和后续牌墙只能评估预测是否命中，不得回填为事前输入，也不得用输赢替代决策质量。

## 核心观点提炼

每条视频先写一份“核心观点总纲”，然后才写各决策节点。总纲必须回答：

- 潇老师真正希望玩家学会的方法是什么；
- 这个方法解决什么通用决策问题；
- 什么公开条件允许它启动，什么新证据会让它减弱、停止或翻转；
- 博主是在优化牌效、和牌可达性、净分、放铳尾风险、剩余巡数还是它们的组合；
- 正式 AI 应学哪个通用机制，以及绝对不能学的本局动作顺序、具体牌名和结局。

核心观点不能只是“这张牌安全”、“要贪”、“要防守”或标题改写。它必须带条件和因果，例如“当改良听口的可达收益仍大于新增的对手威胁与剩余巡数损失时保留进攻路线；公开威胁越过停止线后立即撤退”。

## 能力草案（知识采集阶段）

知识采集阶段只写通用决策问题、公开观察、候选取舍、老师明确的翻转条件、分析者提出的待验证翻转假设与未知项。可记录可能相关的能力，但不得要求生产组件、数值参数或 C# 测试，也不得把草案叫作已验证算法。

## 转换为游戏 AI 算法（后续机制与验证阶段）

对每个核心观点建立可追溯链：

`video evidence -> core thesis -> public state variables -> candidate actions -> objective/constraints -> update or mode-switch rule -> reversal conditions -> production component -> C# tests`

转换时必须完成：

1. **算法问题。** 用不含视频 ID、老师名和具体牌列的一句话定义 AI 要解的问题。
2. **公开输入。** 列出手牌、副露、定缺、牌河时序、可见张数、动作反应、分数、剩余巡数等当时可计算输入；暗手只能是候选分布。
3. **派生状态。** 用公开输入计算实际可达活张、牌型改良空间、花色竞争、对手威胁、释放外部性、尾部损失和时间压力等通用状态。
4. **候选比较与模式切换。** 对所有合法动作比较净分期望、和牌可达性和尾部风险；把“贪”、“稳”、“撤退”写成由状态触发的连续或离散模式，不能写成视频专属 if/else。
5. **先审计旧算法。** 先定位正式 C# 决策入口和已有组件，用本节点检验其行为。已正确覆盖时记录 `validated_existing_algorithm`；只有发现通用机制缺口时才扩展共享算法。
6. **数值与定性分离。** 单视频可以证明方向、比较项和翻转条件，不能产生权重、百分比或阈值。数值只能来自多来源牌谱/仿真校准和独立留出测试。
7. **正式验证。** 每个节点在正式 C# runtime 上绑定期望和真实输出，验证完整状态花色迁移、前提变化，以及与本轮风险有关的结构/结果隔离试验。基线可以失败，候选必须满足预先冻结的验收目标；按 expert-learning-v2.md 分别验收理解、应用和棋力，不以固定测试数换取通过。

## 强制交付与停止条件

知识采集阶段的知识卡必须表达：核心观点、证据窗口、公开观察、候选动作与舍弃理由、老师明确的改意条件、分析者假设、未知项、结果隔离和能力挂接。机制与验证阶段的 AI 应用报告再表达目标项、模式切换/翻转条件、生产组件、实现状态和 C# 测试证据。

以下任一成立时，知识采集只能标记“回看中”；进入后续阶段后只能标记“算法待复核”：

- 只完成视频/OCR/牌面识别，无法说清核心技巧的条件因果；
- 只能复刻本局动作，无法定义通用公开状态、目标和翻转条件；
- 只写“映射到某组件”，但没有可观察的算法行为和真实 C# 测试；
- 为了贴合视频而引入固定牌名、动作序列、单局权重、暗手或未来信息。
