# 真实执行闭环：从公开输入到完整结算

本页在实施已授权 AI 改造或审计学习链路时读取。按当前风险选取实验，不建立默认固定回归清单。

## 1. 公开状态是运行边界，不是一个布尔字段

先冻结实际工作树的代码、规则和可重放程序集，不能将未提交改动归因于本视频。`run_bound_decisions.py` 冻结 C# 源树和二进制；若修改 Godot 桥接/规则，还必须保存并哈希绑定这些实际执行脚本，单独的 AI DLL 哈希不覆盖前端输入变化。

核对实际游戏桥接输入与学习 runner 的同一状态语义。只屏蔽对手暗手数组不够：对手可碰/可杠/可胡权限、未公开听牌标志、顺胡锁、精确可抢杠人数、私有反应事件的存在及其序号，都可能间接泄漏。改变这些内部状态、保持当时公开信息不变，公平策略输入必须不变。自己的手牌、自己的合法反应权限可以保留；不要删去合法动作来伪装公平。该试验必须执行真实输入生产器，不能只测手写 mock。

`BoundDecisionChecks` 可接受 `seat` 和 `public_replay`，调用 `PublicReplayAdapter` 将检查点与公开事件串接成正式 `SichuanStateView`，再进入 `SichuanAiFacade`。报告 `public_context` 保存实际进入决策的四座手牌张数、牌河、副露及事件。输入端点与重放结果必须一致，矛盾直接失败，不排序修复、不截断、不补牌。

当前适配范围是 **checkpoint_window**：支持 Draw、Discard、Peng、MeldedGang；不是完整牌局模拟器。其他事件必须先实现并验证对应规则，否则拒绝。`initial` 包含本家 hand、四家 hand_counts/discards/melds、wall、turn、event_index、next_seat；events 包含 index、seat、type、tile、origin、source_seat、wall_after。未知对手 Draw 的 tile 必须为 null，不能传入暗牌。输入不能附带对手反应权限。

当前输入仍只允许 `grounding=synthetic_transfer`。若视频截断早期牌河、缺墙长/分数或关键信息，必须明确这是围绕已核实事实构建的合成对照，不得改标签为 verified_reconstruction。完整视频重建还需要来源逐字段绑定、未知信息处置和对应实际规则适配，不能凭新接口存在就升级。

补杠节点使用受限快照入口：`tile` 必须是手内第四张、`meld` 中有对应碰牌，已经排净定缺且有补张可用；它实际调用 `SichuanAiFacade.DecideSelfAction`，不接收精确可抢杠人数。`kind=self_added_gang` 拒绝已经成胡的手牌；这种局面必须使用 `kind=self_action` 并显式给出本家 `last_draw`，将合法 Hu、所有结构合法的暗杠/补杠及 Pass 一同交给正式入口。不得为了验证补杠而隐藏合法自摸。`last_draw` 不能由补杠目标自动推断：第四张可能早已保留在手。

上述 self_action 仍限于存在补杠候选的正墙长快照，不是任意自摸阶段模拟器，不能与 public_replay 组合。`wall=0` 属于当前接口不支持范围，不据此推断项目桌规禁止零墙杠。可选 `audit_gang_branches=true` 只观察现有分支选择及风险聚合，不参与生产评分；诊断沿用原状态的启发式风险，不是更新后状态的校准期望损失。

花色迁移必须同时变换端点、本家 last_draw、检查点手牌、逐家牌河、副露、每个事件 tile 和定缺。Unknown/null 保持未知，不变换事件类型。输入顺序本身是信息；不得任意洗牌或把缺失顺序臆造为原片事实。

## 2. 用真实错误决定改哪里

连续候选失败、重建更正或代理指标与对局收益冲突时，先读[学习方法审计](method-audit.md)。先检查来源、被估计的量及数学反例，再决定是否需要新候选；不能把扩大扫描当作默认下一步。审计可得出“不具备实验前提”，不强求产生一次晋级。

先冻结老师论据、候选比较和翻转条件，再跑公平基线。已正确覆盖的例子归为 validated_existing_algorithm。错误必须区分输入重建、四川规则、特征、推断、搜索及老师观点不确定。输入隔离修正是公平性修复，不自动算从视频学到新技巧，也不能把带隐藏信息的旧版当作公平晋级基线。

只扩展通用机制；不以单片或单张牌调权。候选保持未晋级，直到后两步提供有效证据。保留真实失败基线及同一断言，不能用改期望掩盖错误。

## 3. 支持与反例回到原片

能力档案引用本轮实际核验的本地视频窗口、原始牌局组和核心因果。历史卡用于查找窗口，不自动成为新证据。支持例与前提破坏例都要运行真实入口；已有答案只叫回放，不叫盲测。共享相似片段不充当独立来源。

**支持例必须因果触发待验机制。** 报告必须给出机制 reason code、候选诊断量或消融差异，证明最终动作确由本轮机制参与；候选与基线同动作但机制从未计算、诊断量全零或只证明“没有退化”，不能记作支持例。破坏前提例应只改变待验因果前提，并证明机制退出、减弱或使结论翻转；同时改变牌形、巡数和对手威胁的多因素样例只能算边界探查。

分开标记实际执行动作、条件性讲解和后续结果。“可以杠”不等于画面实际杠，更不等于当时处于合法操作窗口；后续自摸只能作为独立端点，不能回填成较早决策已知的补牌。组合技巧不能只测首个 Pass：若核心是“暂不杠并先处理危险张”，应分别检查自摸动作选择、接续弃牌和公开条件变化，缺失的条件仍保留为未知。

## 4. 对局生成与统计分开

`evaluate_paired_strength.py` 只评估提供的数据，不生成真实对局。正式对局使用项目规则引擎走完定缺、摸打、反应、杠、血战和流局结算；强行结束、规则不守恒或后端失败不得算完整样本。记录真实回放、初始墙哈希、实际运行策略/规则/桥接版本、座位、延迟和结算净分。

对局来源必须分层：`natural_full_round` 从合法洗牌、发牌、定缺开始，可在完整结算和守恒通过后进入强度统计；`legal_checkpoint_continuation` 即使检查点合法且最终完成结算，也只用于机制诊断，不能计入棋力晋级；`synthetic_checkpoint` 只用于局部因果测试。人工残局不得标成完整独立对局。

每个检查点必须对 108 张物理牌守恒：所有活动/已胡玩家暗手张数、公开牌河、副露和墙合计一致，任何无法解释的历史牌必须进入明确的合法区域，不能放进“不再使用的 reserve”并从墙中消失。副露不得包含该座定缺花色。检查点的合法性、来源类别、是否有资格进入强度统计必须写入报告，不能从“跑到了结算”反推合法。

在进行强度推断前先检查自然对局暴露度：候选机制必须在冻结的 `natural_full_round` 样本中真实触发，并报告按决策、对局和座位统计的触发数。零触发时结论只能是 `mechanism_unexercised`，不得用零差值声称等强、无回归或已验证；应扩大自然样本或改进通用触发条件，但不得反复查看留出结果后调参。

稀疏机制可以先做“自然机会侦测”，但必须在扫描前冻结候选版本、基线版本、对手版本、种子区间、步长和入选规则。侦测与正式配对必须使用完全相同的对手策略；若侦测时让四座都运行候选，则只有在“首次候选触发前，候选与冻结基线的所有动作（包括反应）完全等价”时才合法；只比较弃牌同动作而忽略碰/杠/胡/过策略差异，会改变公开历史并使机会筛选失效。侦测从正常洗牌、发牌、定缺开始，只记录候选首次分歧前自然到达的公开触发事件；入选不得读取或依赖胜负、净分、点炮或后续摸牌。冻结区间内满足条件的种子必须全部入组，不得挑选有利案例。随后仍要对入选组从自然开局跑完基线/候选双臂、四座轮换和完整结算，并逐组在侦测记录的首次触发座位精确复现候选机制；不得用其他组或其他座位的多次触发补足总数。 这种结果只能支持与入选条件完全一致的“条件能力”晋级；不能代替未筛选自然总体的全局强度结论。用于正式晋级时，另需一组未参与调参的广泛自然对局检查完整性和灾难性回归；若稀疏到零触发，该组仍不能声称“无回归”。

机会侦测结束后必须用 `validate_opportunity_scan.py` 将每个报告逐批绑定到冻结计划，检查版本哈希、完整种子序列、无重复/遗漏、首次触发即停、无隐藏信息、无结果字段、两副露范围以及所有命中全量入组；校验失败的扫描只能进入失效记录，不能生成强度计划。

先冻结方案再生成结果。每个独立种子及四座轮换都运行 baseline/candidate 两臂，其他三席用同一冻结对手。相同初始墙不表示后续摸牌会相同：双方动作导致的分歧是正常结果。训练与留出按原始牌局组隔离。单次四席候选对旧策略所得净分、内部 oracle regret 或有限测试成功，都不能代替两臂净分差。

无增益或置信区间未过线时，闭环应输出“候选未晋级 + 失败原因 + 下个能力缺口”。不得为了结束任务生成有利数据、取消反例或反复查看留出后调参。闭环能运行与 AI 已变强分别报告。
