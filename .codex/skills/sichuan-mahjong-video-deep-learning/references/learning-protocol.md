# 单视频证据化深学协议

## 完成定义

播放到结尾、认清图像牌面或读清字幕都不等于学完。只有能以博主主视角重建公开信息、候选动作、推理链、概率含义和反事实边界，准确说清本片核心观点，并将其迁移为正式四川麻将 AI 的通用决策机制且通过真实 C# runtime 验证，才可标记“已吃透并应用”。

## 证据等级

- A：博主字幕或语音明确陈述。
- B：原视频牌面、牌河、副露或动作可直接确认。
- C：依据四川麻将规则从A/B证据推导；必须写出推导。
- D：证据不足的待验证假设；不得进入AI规则。

## 工作流

1. 固化URL、视频ID、标题、作者、发布日期标签、时长、原片哈希；页面发布日期与视频画面日期不一致时分别记录，不擅自合并。
2. 从00:00生成每秒基线帧与字幕OCR，建立客观事件时间线。
3. 先用全片时间线写“核心观点总纲”：博主反复比较的问题、允许开始的条件、促使攻守切换的新证据、优化目标及不得进入 AI 的本局信息。
4. 标出每个摸打、碰杠、胡或不胡、攻守切换节点；不清楚就扩大前后窗口并高密度抽帧。
5. 对每个节点记录本家手牌、四家副露、逐家弃牌时序、摸切/手切可见性、候选动作和结果。
6. 将博主的“观察→候选隐藏结构→规则/行为似然更新→风险/收益比较→动作”写成推理图；明确哪些步骤是原话、哪些是重构，并给每个核心结论绑定时间戳和证据帧。
7. 概率必须说明对象、样本空间、可见张、未知牌和假设。信息不足时只写相对变化，不伪造百分比。
8. 至少做三项反事实：改变出牌时序、可见张数、我方收益/听牌状态，检查结论是否翻转。
9. 把每个知识单元从具体动作提升为算法合同：通用问题、公开状态变量、动作空间、目标项、不变量和翻转条件。具体牌张只能作为例子。
10. 先审计正式 C# 入口与已有共享算法；已覆盖时验证并复用，存在通用能力缺口时才实现。每个核心观点都要有“观点→公开输入→状态→决策规则→代码组件→测试”追溯链。
11. 做花色置换、结构变体、破坏前提和结果不变性盲测；失败则回到原则层修订，不能增加视频专属模式补丁。
12. 写`evidence-index.json`和新版`ai-application-report.json`，运行证据包验证器与真实 C# runtime 测试；验证失败时不得靠修改状态文字绕过。

## 语义自检

- 能否不看结论，从关键时间点还原博主当时看见了什么？
- 每个“可能有某牌”是否同时列出支持证据、反证和仍未排除的替代结构？
- 是否区分规则不可能、行为上不太可能和只因结果发生而事后觉得可能？
- 是否说明概率的事件、条件、未知样本空间与无法校准之处？
- 是否能解释为什么另一个候选动作不如博主动作，而非只说“高手这样打”？
- 是否能用带触发条件、优化目标和攻守翻转条件的话，准确概括本片核心观点？
- 改变先后顺序、可见张、分差或剩余巡数后，结论是否按逻辑变化？
- 换一门花色和具体点数后，算法是否只随状态量变化而不是随牌名变化？
- 是否能在不写视频 ID、不识别固定动作序列、不新增单局权重的情况下实现？
- 是否有真实 C# runtime 证据证明该原则已影响候选排序或动作选择，而不是只在报告中列出组件路径？

## 强制停止条件

- 视频ID、时长或哈希未验证。
- 关键牌面、座位、动作顺序存在未解决歧义。
- 只能复述结论，无法解释候选牌为何被排除。
- 将博主定性判断擅自改写成精确概率。
- 尚未通过反事实和迁移验证。
- 只能复刻本局动作，不能写出通用状态、目标和翻转条件。
- 只认清了视频、图像或字幕，却无法概括本片的核心观点及其条件因果。
- 只声称已映射到 AI，没有可观察的生产算法行为和真实 C# runtime 证据。
- 生产实现含视频专属序列、牌名乘数、结果泄漏或单视频数值参数。

上述任一成立，不得声称已应用或晋级正式策略。证据身份与关键局面已可靠时，允许先开发可撤回的候选算法，再补相关验证；尚未过测必须标 candidate/pending，而不是“已吃透并变强”。采用 expert-learning-v2.md 的分阶段合同，避免“必须先验证完成才允许写可验证代码”的循环。

验证器通过但上述语义自检不通过，同样保持“回看中”。
