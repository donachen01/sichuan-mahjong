# 四川麻将 16 份 PDF 学习成果落地修正实施方案

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 16 份四川麻将资料中的规则、精确牌形、排列组合推断、清一色预下叫、期望收益、多人博弈和连续策略，落到当前四川麻将新版工程的规则、C# AI Core、Godot 桥接、独立评分、UI 解释和回归测试中，使骨灰透视和非透视 AI 都能稳定按四川老手逻辑决策。

**Architecture:** 采用“受控重写 AI Core、保留外部桥接合同、分阶段替换旧引擎”的方式。Godot 继续拥有牌局状态机、合法动作闸门、动画和最终结算；C# 拥有精确牌形分析、非透视后验、整局策略、统一行动树和决策解释。旧 `SichuanDecisionEngine`、`SichuanReactionDecisionEngine` 和 `SichuanSelfActionDecisionEngine` 不再继续堆叠权重，逐步收缩为兼容适配器，最终由统一决策器接管。

**Tech Stack:** Godot 4.6.2 .NET、GDScript、C#/.NET 10、NativeAOT iOS、Godot headless 回归、C# console smoke、JSON/JSONL 对局证据。

## 一、当前代码诊断与重写范围

### 已有可复用能力

- `SichuanShantenEngine` 已支持普通牌与七对向听，适合作为精确牌形层的入口。
- `SichuanBeliefEngine`、`SichuanOpponentRangeEngine` 已有后验数据结构、缓存和过碰/过胡证据入口。
- `SichuanRoutePlanEngine`、`SichuanRoundBrainEngine` 已有路线、承诺度、切换滞回和四家隔离的雏形。
- `SichuanExpectedScoreEngine` 已有净收益字段，但目前主要是启发式估算。
- `SichuanLimitedLookaheadEngine` 已有“摸一张、再弃一张”的一层前瞻。
- `GameState.gd` 已有定缺、血战、顺胡锁、杠事件、退杠、呼叫转移、查叫、花猪和逐动作 JSONL 日志。
- `sichuan_old_hand_discard_scorer.gd` 已与线上总分隔离，可作为独立裁判迁移入口。

### 必须替换或拆分的部分

- `SichuanDecisionEngine.cs` 约 1800 行、`SichuanReactionDecisionEngine.cs` 约 900 行，当前职责和权重耦合过重；不再继续局部叠加补丁。
- `SichuanReactionDecisionEngine` 当前 `canHu` 时直接返回 100000 分胡牌，不能实现 PDF 6/13 的策略性过胡。
- `SichuanSelfActionDecisionEngine` 当前自摸可胡直接胡牌；自摸通常应胡，但仍需进入统一合同并明确只有规则允许时才比较。
- `SichuanOpponentRangeEngine` 当前主要按中心张、花色热度等线性权重推断，不是 PDF 7 的排列组合后验。
- `SichuanExpectedScoreEngine` 当前番值、点炮损失、自摸占比和流局概率均为近似权重，尚未使用完整分支收益。
- `SichuanSelfDrawProbabilityEngine` 使用独立重复抽样近似，未精确处理摸牌次序、存活人数和牌墙条件概率。
- `SichuanLimitedLookaheadEngine` 只看下一摸和下一弃，不能完成 PDF 9 的清一色预下叫规划。
- `SichuanStateView` 缺少手切/摸切、公开动作时序、具体副露类型、每家手牌张数、顺胡锁番值、最近杠链等关键证据。
- `fan_resolver.gd`、`score_resolver.gd`、`GameState.gd`、UI 中仍保留报叫、报杠、卡二条、归和内江分支；即使默认关闭，也会污染四川规则和 AI 名词。

### 重写边界

- 重写 C# 决策内核和相关模型。
- 保留 `SichuanAiFacade` 对 Godot 的三个主入口名称，先内部转发到新内核，避免一次性破坏 NativeAOT 桥接。
- 保留 Godot 牌局执行状态机；只扩充传输状态、删除内江专属死分支、接入新结果。
- 规则计算在 C# 建立纯函数镜像供搜索使用，并通过合同测试与 Godot 最终裁判逐例对齐；不允许两个规则源长期无校验分叉。
- 规则冲突取值顺序固定为：`四川麻将项目规则基线_最终版_v1.md` > 当前四川规则回归测试 > 老四川规则文档 > PDF 经验文章；最终基线未冻结的数值先参数化并保持当前线上行为，不从内江规则或个人猜测补值。
