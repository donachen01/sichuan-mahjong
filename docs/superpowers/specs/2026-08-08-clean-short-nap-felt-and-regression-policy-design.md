## 2. 详细根因

### 2.1 水渍已经烘进 BaseColor

当前 `tools/3d/generate_sichuan_table_v2.py` 使用 `28×28`、`96×96` 和 `360×360` 三层平滑噪声，并把三层共同写入 BaseColor 明暗：

```python
tone = (
    (broad - 0.5) * 0.028
    + (medium - 0.5) * 0.018
    + (fine - 0.5) * 0.006
)
base *= 1.0 + tone[:, :, None]
```

数值分解表明，当前 BaseColor 总亮度标准差中约 `73.6%` 在 `28×28` 低频层仍然存在。当前 Normal 在相同尺度的低频分量接近 0，Roughness 的低频分量较小，因此真机大斑块的主要来源是 BaseColor，不是法线凹坑或金属高光。

### 2.2 UV 把 28×28 噪声放大成约 8×13 块

Blender 5.2.0 LTS 读取最终 GLB 后确认：

- 对象：`TableFelt`
- 材质：`DeepEmeraldShortNapFelt`
- UV：`UVMap`
- 顶面 UV 范围约为 `U 0.6556–0.9423 / V 0.5037–0.9799`

桌面顶面只使用整张纹理约 `28.7% × 47.6%` 的区域。因此 `28×28` broad 噪声映射到实际桌面后，只剩约 `8.03 × 13.33` 个大色块。真机截图中大片、不规则、互相连接的水渍形状与这一有效尺度一致。

UV 本身没有损坏，问题是生成器没有按真实 UV 占用范围设计空间频率。本轮保留现有几何和 UV，通过移除中低频底色变化解决根因，并把实际顶面 UV 区域纳入验证。

### 2.3 GLB 与导入链路没有篡改源图

`res/art/materials/table_v2/` 的三张作者贴图与 GLB 导出的 `res/art/3d/sichuan_table_v2_felt_*.png` 逐像素完全一致，最大通道误差为 0。Blender 中 PBR 节点也正确连接 BaseColor、Normal 和 ORM。问题在作者贴图生成策略，不在 GLB 导出、材质连接或错误贴图。

### 2.4 iOS 过滤让错误更显眼，但不是根因

iOS 使用带 mipmap 的移动纹理。正常牌局距离会先过滤掉高频短绒，而低频 BaseColor 云斑会保留。移动端压缩和 Filmic/暖光会增强斑块的可见度，但不会凭空制造截图中的形状。因此先修作者源图；只有源图通过而 iOS 仍出现额外压缩块时，才单独调整三张桌布贴图的移动导入质量。

### 2.5 旧门禁验错了对象

旧验证只要求全图 BaseColor 亮度变异系数位于 `0.006–0.018`，没有检查变化发生在哪个空间尺度。这个下限反而鼓励加入可见低频噪声。旧四档桌面截图的自动检查也只检查绿色中位数和通道比例，没有检查连通斑块、低频能量或实际顶面 UV 区域。

## 4. Blender 干净短绒 PBR 设计

### 4.1 生成工具

- 使用 `/Applications/Blender.app/Contents/MacOS/Blender`。
- 当前版本为 Blender `5.2.0 LTS`。
- 继续由 `tools/3d/generate_sichuan_table_v2.py` 确定性生成三张 2048×2048 贴图和 `res/art/3d/sichuan_table_v2.glb`。
- 保持 `TableFelt`、`DeepEmeraldShortNapFelt`、桌体尺寸、位置、圆角、UV、相机和运行时资源接口不变。

### 4.2 BaseColor

- 完全移除 broad 和 medium 低频噪声对 BaseColor 的影响。
- 不设置“必须达到某个变异系数”的下限。
- 主体为统一的启动图校准暖绿。
- 如保留微小颜色活性，只允许使用在实际顶面 UV 映射后仍属于像素级的高频、零均值扰动；正常牌局距离和 mipmap 后应自然消失。
- 禁止云纹、色岛、条带、径向斑、暗角、污渍、磨损、品牌图案和已烘焙光影。

### 4.3 Normal

- 保留多方向、近等权重、短尺度微绒。
- Normal 只承担近距离细微触感，不承担大尺度明暗变化。
- 不允许 broad/medium 高度场，不允许单一方向成为主导。
- 继续使用较低 Normal 强度；若真机仍能直接看到纤维线，优先继续降低，不通过增加 Roughness 或颜色噪声掩盖。

### 4.4 ORM

- AO 保持接近均匀，桌边和牌的接触深度由几何、阴影和 SSAO 提供。
- Roughness 保持高粗糙度、低变化，只产生柔散响应。
- Metallic 固定为 0。
- Roughness 不复用 BaseColor 噪声，也不生成能在牌局距离辨认的块状结构。

### 4.5 灯光与移动压缩边界

- 第一轮只修作者材质，不修改环境光、主光、相机或 Filmic。
- Blender 贴图和 Metal 桌面通过后，若整体颜色仍与启动图有系统偏差，才允许小幅调整桌面环境光/主光颜色或能量；不得新增灯光。
- 只有修复后的源图在桌面 Metal 干净、但 iOS 真机出现源图中不存在的块状压缩伪影时，才提高三张桌布贴图的移动导入质量。不得用压缩设置掩盖源图低频噪声。

## 5. 验收设计

### 5.1 先建立失败测试

在修改生成器前，先更新 `tools/verify_splash_matched_felt.py`，让当前 2.6.30 贴图因低频水渍失败。新检查直接读取 Blender 最终顶面 UV 范围，不再只量整张纹理。

当前失败基线必须至少满足：

- 整张 BaseColor 的 `28×28` 低通标准差占总标准差约 `0.736`；只量实际顶面 UV 区域时约 `0.763`，两者均超过新上限。
- 实际顶面 UV 的 broad 有效尺度约为 `8×13`，判定为可见宏观图案。

### 5.2 新材质门禁

- BaseColor 顶面 UV 区域的 `28×28` 低通标准差占总标准差比例 `<= 0.20`。
- BaseColor 不设最小变异下限；总亮度变异系数只设上限 `<= 0.004`。
- 顶面 UV 区域低频亮度 `P99-P1 <= 1.5/255`。
- Normal X/Y 均方能量比 `<= 1.30`，且 28×28 低频比例 `<= 0.05`。
- Roughness 中位数保持 `0.86–0.90`，`P99-P1 <= 0.02`，Metallic 最大值为 0。
- 连续两次 Blender 生成的 BaseColor、Normal、ORM 和 GLB SHA-256 完全一致。

这些是本次桌布专项检查，不加入任何固定回归清单。

### 5.3 视觉验收

按顺序提供：

1. 启动图桌面参考。
2. 用户提供的 2.6.30 iOS 水渍失败基线。
3. 修复后的本机 Metal 空桌面截图。
4. 修复后的本机 Metal 正常牌局截图。
5. 修复后的 iOS 真机同构图截图。

必须人工检查：

- 整张桌面为均匀自然暖绿。
- 没有可辨认的大块明暗轮廓、云斑、水渍或织纹。
- 近看存在轻微短绒响应，但不形成条纹。
- 牌、中心器和桌框仍有可信接触关系。
- 真机结果不能只用颜色中位数代替人工逐图比较。

### 5.4 聚焦验证，不建立清单

本轮只执行与改动直接相关的检查：

- Blender 5.2.0 LTS 两次确定性生成。
- 更新后的桌布专项验证器，先红后绿。
- Godot 导入与桌体材质/3D Stage 聚焦测试。
- 一档主要 Metal 空桌面和正常牌局截图；必要时补目标 iPhone 分辨率。
- iOS 2.6.31 全新导出、NativeAOT、Xcode 签名构建、安装、版本回读、启动和真机截图。
- `git diff --check`。

以上验证不会写入新的固定 manifest，也不会在后续任务中默认继承。
