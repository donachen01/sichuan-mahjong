# 四川麻将 2.6.33 绒布触感、哑光余牌与自然摸牌设计

日期：2026-08-08

状态：用户已批准方案 A，等待书面规格复核后进入实施计划。

## 1. 目标

在保持 2.6.32 已确认的自然暖绿桌布颜色、干净均匀底色和牌桌物理一体感的前提下，完成三项改造：

1. 让正常牌局距离也能感受到与启动页同类的细密短绒，而不是一块均匀平绿平面。
2. 删除余牌数字旁边遮挡视线的镜片亮点，使数字区域稳定、哑光、清楚。
3. 删除浅蓝色旋转菱形；新摸牌改为真实麻将桌上的右侧独立牌位，玩家出牌后再排序归位。

完成后版本升级到 `2.6.33`，生成新的 iOS 发布产物，在设备可用时覆盖安装并验证启动，同时将本轮白名单改动提交并推送到现有 GitHub 远端。

## 2. 已确认根因

### 2.1 桌布短绒不明显

当前 BaseColor 为均匀暖绿，正确避免了 2.6.30 的低频云斑和水渍。短绒全部依赖 Normal 与 Roughness：Normal 使用约 `520–830` 周期的四组高频方向场，Roughness 为 `0.86–0.90`。在正常牌局距离，特别是 iOS mipmap 过滤后，高频法线先被过滤；高粗糙度、较强环境光和更接近顶光的主光又进一步压低斜向明暗差，因此成品只剩均匀绿色。

本轮不能通过恢复 BaseColor 中低频噪声解决，否则会重新引入已修复的水渍问题。

### 2.2 余牌数字亮点

余牌数字位于 `CounterGlassLens` 上方。镜片当前使用透明烟玉玻璃、低粗糙度和透射；数字同时使用较亮暖象牙色与较粗深色轮廓。玻璃镜面响应和高对比轮廓叠加后，在数字旁形成局部亮点和光圈，干扰数字读取。

### 2.3 蓝色摸牌菱形

现有摸牌状态使用无光照纯蓝四面菱锥，并以 `126°/s` 持续旋转。它悬浮在牌面上方，颜色、形态和运动都与胡桃木、烟玉、古铜和暖象牙牌桌语言脱节；还需要独立旋转父节点与逐帧处理。

## 3. 选定设计

采用“双色阶稳定、双尺度短绒、哑光计数面、右侧自然摸牌位”的方案 A。

### 3.1 双尺度物理短绒

- BaseColor 继续保持当前均匀自然暖绿，不加入 broad/medium 低频色岛、暗角、径向斑、污渍或明暗云层。
- Normal 从“只有极高频纤维”改为两层：
  - 中短绒层使用无主方向、带限的随机纤维/颗粒高度场，尺度应能在正常牌局距离与 iOS mipmap 后保留轻微柔散变化。
  - 微绒层保留多方向高频纤维，只负责近看细节，不得形成规则纵纹、横纹或织带。
- 两层必须接近各向均衡；Normal X/Y 能量比继续不高于 `1.30`。
- 中短绒必须是高通或带通结构，不允许把低频块状噪声写入高度场。
- Roughness 从当前 `0.86–0.90` 收敛到约 `0.83–0.87`，保留高粗糙度软响应，但不再完全死哑。
- Metallic 保持 `0`，AO 保持近似均匀。
- 不增加运行时绒布 Shader、不增加纹理采样器、不增加逐帧材质动画；继续由 Blender 5.2 确定性生成 2048 PBR 贴图和桌体 GLB。

目标效果：正视大面积仍然均匀干净；斜光和牌旁局部能看到细密、无方向性的柔绒颗粒；不能出现闪点、丝绸亮带、塑料反光或水渍轮廓。

### 3.2 哑光余牌计数面

- `CounterGlassLens` 保留既有几何边界和计数器尺寸，但材质从透明玻璃改为不透明哑光烟玉嵌片。
- 关闭透射与透明混合；Metallic 接近 `0`，Roughness 提高到约 `0.68–0.76`，不使用清漆亮点或发光。
- `CounterBronzeBezel` 保留低调古铜边界，不扩大、不发光、不增加第二圈描边。
- 余牌数字使用柔和暖象牙色，减小深色 outline 厚度；必须在烟玉底上清楚，但不能形成白色光圈。
- 数字保持静态、无旋转、无呼吸、无发光、无深度遮挡问题。
- 四方向红色激活片、方向文字、计数器半径、圆弧切口和中心器总三角面预算保持不变。

### 3.3 自然摸牌流程

摸牌不再使用任何悬浮图标，改为真实牌序和空间位置表达：

1. 新摸牌从既有运动起点进入，以约 `200ms` 行进和 `50ms` 收束落到本家手牌最右侧。
2. 新摸牌与已整理手牌之间保留一段清楚但克制的物理间隔；间隔参与 18 张极限布局的统一缩放计算，不能越过底部或左右安全区。
3. 玩家出牌前，新摸牌保持在右侧独立牌位，不自动插入排序，不使用颜色、图标或持续动画。
4. 如果玩家直接打出新摸牌，它从右侧独立牌位沿既有弃牌运动进入弃牌河。
5. 如果玩家打出其他牌，弃牌运动完成后，保留的新摸牌以约 `180ms` 平滑移入按花色/点数排序后的正确位置。
6. 排序移动只改变展示位置，不改变 tile id、可点击性、规则手牌、缺门约束或权威状态。
7. 胡牌展示、结算牌列和已胡平扣布局不保留右侧摸牌间隔，继续使用最终排序后的既有展示合同。
8. 删除蓝色菱锥网格、无光照蓝色材质、旋转速度常量、抵消倾角父节点和相关 `_process`；摸牌静止后不存在逐帧开销。
9. Reduced Motion 模式仍保留正确的最终位置，但可将摸牌/归位 tween 缩短或直接落到目标位，不得重新显示图标。

## 4. 状态与数据流

- `human_last_draw_tile_id` 继续作为新摸牌权威标识，不增加第二份 gameplay 状态。
- Stage 构建本家展示列表时，将该 id 对应牌从排序列表中暂时移出并追加到右侧独立牌位。
- 玩家完成出牌后，下一份权威快照若该 id 仍在手牌中且已不再是当前待处理摸牌，则 Stage 使用既有 tile node 执行排序归位，不重建牌体。
- 若该 id 已进入弃牌列表，则既有 tile id 运动路径负责从右侧位置进入弃牌河。
- 不允许前端自行决定出牌、自动整理规则或修改 GameState 手牌顺序；这里只改变 3D 展示列表和目标 Transform。

## 6. 测试与验收

### 6.1 测试驱动顺序

修改生产代码前，先更新聚焦门禁并观察当前实现按预期失败：

- 桌布验证器拒绝“只有超高频、mipmap 后无可见中短绒”的当前 Normal，同时继续拒绝 2.6.30 低频水渍基线。
- 中心器测试要求计数镜片不透明、高粗糙度、无透射高光，并检查数字不使用粗光圈式 outline。
- Tile/Stage 测试要求无蓝色菱形、无旋转进程，新摸牌位于最右侧独立位；打出其他牌后归位，直接打出时从独立位离开。

### 6.2 自动门禁

- BaseColor 顶面 UV 区域低频能量、亮度跨度和总变异继续满足 2.6.31 干净桌布上限，不允许回退。
- Normal X/Y 能量比 `<= 1.30`；低频比例继续受限；新增中短绒频带能量下限，证明细节不是全部落在移动端会过滤掉的超高频。
- Roughness 中位数与跨度符合新范围，Metallic 最大值为 `0`。
- Blender 连续两次生成的 BaseColor、Normal、ORM、桌体 GLB 和中心器 GLB 哈希分别一致。
- 本家普通 14 张、含副露、18 张压力布局和超宽 iPhone 视口均不溢出；新摸牌独立间隔清楚，排序归位后恢复连续牌距。
- 新摸牌、归位和直接打出三条状态路径使用同一 tile id，点击命中保持有效。
- `SichuanVersionConsistencyRunner` 通过。

### 6.3 真实渲染

- Apple M1 Pro / Metal / Forward+ 至少拍摄空桌、正常牌局、新摸牌独立位、归位后和密集牌局画面。
- 覆盖 `1365×768`、`2048×1152`、`2556×1179`；必要时补当前 iPhone 逻辑宽高比。
- 人工检查桌布能感知短绒但无水渍/条带；余牌数字附近无亮点、光圈或遮挡；新摸牌右侧位置自然、不越界、不与 HUD 重叠。
- iOS 安装后至少取得用户真机或远程截图才能声称 iPhone 画面通过；仅有安装和启动不能替代画面验收。

### 6.4 聚焦验证策略

本轮按风险选择单项 Runner、材质验证器、C# Release 构建、iOS 发布检查和 `git diff --check`。这些项目不会写成新的固定回归清单，也不会恢复已删除的 27 项 manifest。

## 7. 冻结范围
