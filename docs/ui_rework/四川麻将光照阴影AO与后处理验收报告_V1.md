# 四川麻将光照、阴影、AO 与后处理验收报告 V1

## 1. 结论

第五阶段 **PASS**，但属于严格门槛下的临门线通过，不是宽松放行。主设计师与独立设计师均为 `23/25`，每项不低于 `4/5`，`P0=0`、`P1=0`。

## 2. 八轮真实校准

本阶段共保留八轮 1365×768 实机渲染：

1. 首轮把阴影方向改为右下，但阴影过长、侧家死黑，且桌面/牌面三套指标全失败；
2. 恢复原能量后桌面通过，但牌面与接触阴影失败；
3. 引入麻将牌专用补光层后，桌面和牌面仍越线；
4. 牌面改为印刷层色彩稳定、实体树脂层接受真实光照，牌面指标通过，但桌面与阴影仍失败；
5. 降低环境光后桌面/牌面通过，阴影 P5 死黑；
6. 拉长阴影能提高覆盖率，但造成更硬、更长的廉价投影，真实视觉失败；
7. 撤销过度拉长，局部光影通过，桌面上段色差仍超线；
8. 仅微调远端桌布源色，三套分析器才同时通过。

验收中还发现参考图牌墙、当前立手和中央牌覆盖面积不同，直接强求相同总暗影覆盖率会诱导错误的长硬阴影。最终标准改为局部 P5 深度、当前几何合理覆盖率、固定光向合同和双设计师目视，修改原因已写入标准，不隐藏失败过程。

## 3. 最终量化结果

### 3.1 光影

- 中央牌区 P5/中位亮度比：`0.6163`，门槛 `0.45–0.72`；
- 深阴影覆盖率：`5.35%`，门槛 `4%–10%`；
- P5 亮度：`64.36`，门槛 `≥45`；
- 光向合同：DirectionalLight 射线落向世界右/近端，对应屏幕右下；
- 实时灯 `2`，投影灯 `1`，无逐牌灯和逐牌物理；
- SSAO `radius 0.72 / intensity 1.15 / power 1.35 / detail 0.45`；
- shadow opacity `0.94`、shadow blur `1.55`，未使用方向光 PCSS。

### 3.2 前阶段回归

桌面三段 RGB：

- 上段 `(94,128,179)`，目标距离 `16.31`；
- 中段 `(84,109,159)`，目标距离 `15.65`；
- 下段 `(78,96,147)`，目标距离 `13.86`。

桌面分析器全部通过。牌面/牌背：

- 牌面 `(243,241,240)`，目标距离 `14.35`，Q90 未过曝；
- 牌背 `(43,148,49)`，目标距离 `4.0`；
- 绿字/红字对比 `9.31 / 7.02`。

牌体分析器全部通过。印刷白面与字面使用色彩稳定层，真实树脂侧边仍接受主光、补光、阴影和 AO，因此不是把整张麻将牌变成无光照贴片。

## 4. 移动渲染路径纠正

原 `gl_compatibility` 实测把桌面抬亮约 25–35 级，桌面目标蓝分析失败，明确为 P1。项目移动端渲染方法升级为 `forward_plus`，与桌面 Metal 证据一致，并由 `SichuanLightingQualityRunner` 锁定。

这项升级只证明画质路径正确；iPhone 上的持续帧率、发热和耗电必须在第七阶段另行验证，不能用桌面截图冒充真机性能。

## 5. 回归与四分辨率

四档 Metal 图 `4/4`：无黑柱、透明洞、阴影断层或边缘漏光。十项聚焦 Godot Runner 全部 `exit 0`，包括新增 `SichuanLightingQualityRunner`；C# Release `0 warning / 0 error`；三个 Python 分析器编译和 `git diff --check` 通过。

Godot 退出仍打印项目既有 RID/ObjectDB 清理提示，本报告不将其写成“无警告”。
