# 四川麻将动效、触控、性能与 iOS 交付验收标准 V1

## 1. 阶段边界

本阶段是“锦夏蓝庭”3D 改造的最终工程门禁。前六阶段已经通过的摄像机、空间排布、牌体、桌体、光照、HUD 和状态合同全部冻结；只允许修正动效时长/还原、触控命中与去重、Forward+ 性能阻断、版本和发布链路，不再用主观装饰修改扰动已通过画面。

## 2. 动效门槛

1. 动作按钮入场、按压、焦点和提示反馈时长全部 `≤220 ms`；不得缩小或移动真实 Button/Control 点击矩形，只能动画内部视觉层。
2. 选牌抬升后点击映射仍指向同一 `tile_id`；最新弃牌、推荐、危险和选中标记互不复用同一语义。
3. 已胡倒牌、点炮来源和回合 HUD 在一次快照刷新内完成；动画期间不得恢复可点击出牌目标。
4. `accessibility/reduced_motion=true` 时所有非必要循环、入场位移和脉冲立即静态复位；合同测试不得产生残留 Tween。
5. 动效合同自动测试 `20/20` 连续执行通过，无一次状态漂移。

## 3. 触控门槛

1. 本家每张手牌的实际投影点击矩形最小边 `≥44 pt`；定缺和主要动作按钮 `≥88×72 px`；工具栏主项 `≥184×76 px`，退出 `≥76×76 px`。
2. 左上入口及 AI、难度、明牌三项各连续真实触摸 `20` 次必须 `20/20` 生效；同一次 iOS touch + mouse 模拟双事件必须只执行 `1` 次。
3. AI 标题拖动到四角后，展开/收起、滑杆和推荐按钮均不得被拖动状态吞掉；透明度 `0/25/50/75/100%` 全部可达。
4. 3D 牌点击必须从屏幕坐标映射到正确 `tile_id`；不可点击牌、已胡手牌和模态遮罩后牌桌不得穿透。
5. 触控、恢复 UI、实时响应、HUD 状态和 3D 舞台五组聚焦 Runner 全部通过；全量 Runner 不得出现功能回归。

## 4. 性能门槛

1. 项目移动渲染方法必须为 Forward+，实时灯 `≤2`、投影灯 `≤1`、RigidBody `0`，不得逐牌创建灯光或材质实例爆炸。
2. 真实 Metal 桌面压力场景至少连续 `600` 帧：平均 FPS `≥55`、1% low `≥45`，进程峰值常驻内存 `≤1.2 GB`；采样脚本和原始结果必须保留。
3. 四分辨率真实 Metal 状态矩阵不出现黑帧、透明洞或首帧未初始化；最终 16 图检查仍为 `16/16`。
4. iPhone 自动验证至少覆盖安装、启动、进程连续存活 `≥60 s` 和设备未报告崩溃；若 Xcode/Instruments 能读取性能轨迹，则保存轨迹并报告；工具权限或设备状态不能被伪装成已验证。
5. “在 iPhone 上实际打一整局、连续 10 分钟的持续帧率/发热/耗电”属于人工设备验收。自动安装、启动或桌面 Metal 数据均不得替代；未由用户现场完成时必须在最终报告中明确列为待人工确认，不影响已达到的自动交付层级。

## 5. iOS 产物与安装门槛

1. 正式版本同步更新 `project.godot`、`export_presets.cfg`、`VERSION.md`、`README.md` 和 `CHANGELOG.md`；Android `version/code` 与语义版本对应，iOS short/build version 相同。
2. Godot .NET iOS Xcode 工程重新导出；Xcode `Release-iphoneos` 必须 `BUILD SUCCEEDED`，不得复用旧 App 冒充新包。
3. App `CFBundleShortVersionString / CFBundleVersion / Bundle ID` 与发布记录一致；主程序与 NativeAOT framework 都是 `arm64`。
4. `codesign --verify --deep --strict` 通过；Xcode 工程源 PCK 与 App 内 PCK 的 SHA-256 完全相同；最终 PCK 必须包含本轮关键脚本/Shader/GLB。
5. `devicectl` 覆盖安装到 `dona‘s iPhone`，设备安装库确认新版本；用 `--terminate-existing` 启动并记录 PID，60 秒后仍可在设备进程列表找到。
6. 构建、签名、安装、启动、进程存活、人工完整牌局分别报告，不允许互相替代。

## 6. 最终放行

- 全量 Godot Runner、C# 构建、Python 工具、截图矩阵、差异检查均通过；
- iOS 构建、签名、架构、PCK 一致性、安装、版本和启动存活全部通过；
- 任一崩溃、错误包版本、签名失败、安装失败、关键触控偶发失效、已胡牌仍可点击，均为 P0/P1，必须修复后重跑；
- 真机完整一局若尚未由用户人工完成，最终状态写作“自动交付完成，人工长时牌局待确认”，不得写成“全部真机体验已验证”。
