# 四川麻将商业成熟效果改造方案 V3

## 1. 改造结论

本轮不照搬市面参考产品的蓝色桌面、卡通头像或高饱和塑料牌背，而是保留现有“蜀锦玉案”品牌方向：低饱和墨玉绿、暖象牙麻将、旧铜描边、左上暖光和克制蜀锦暗纹。

商业成熟度的提升集中在四个层级：

1. 牌桌从平面背景升级为有前后透视、桌沿厚度、座位围合和视觉焦点的固定视角空间。
2. 四家从文字数据框升级为有头像徽章、姓名、积分、定缺、庄家、已胡和当前行动状态的身份组件。
3. 中央余牌牌匾升级为四向回合仪表，统一表达余牌、当前行动方和牌局状态。
4. 选牌、最新弃牌、碰杠胡、定缺和工具抽屉使用统一的短动效、形状标记、声音与触控反馈。

## 2. 技术路线

### 2.1 本轮采用固定视角 2.5D 表现层

当前规则、AI、快照分发、四家牌面布局、触控和 iOS 打包已经稳定，主牌桌使用 `Node2D + CanvasLayer + Control`。直接把所有牌面迁入全 3D 会同时改动牌面绘制、碰撞、触控、嵌入副露、AI 标记和截图回归，风险大且无法保证一次迁移后的移动端手感。

本轮采用成熟移动棋牌常用的固定视角 2.5D：

- 程序化透视桌面和桌沿建立统一空间。
- 麻将继续使用已验证的大尺寸 2D 牌面资源，但统一厚度、接触阴影和光源方向。
- 中央回合仪表、头像徽章和操作按钮使用原生 `Control`，保证安全区和触控可靠。
- 保留现有 `MahjongTile3D`、`HandStage3D` 作为后续真实 3D 资产试验层，不让试验路径影响正式牌局。

该路线的目标不是伪造开放式 3D，而是在固定横屏摄像机下达到参考产品的空间完整度、信息层级与商业手感。

### 2.2 表现层与规则层继续隔离

```text
GameState / C# AI / 四川规则
            ↓ snapshot
MainSceneV2 表现协调
   ├── Perspective Table Surface
   ├── PlayerUI / TileVisual2D / HandCanvas2D
   ├── SeatHUD Identity System
   ├── Center Turn Compass
   ├── TableActionBar
   └── AI / Utility / Settlement Overlays
```

UI 只读取快照和发出动作，不重新计算合法出牌、番型、AI 决策或结算。

## 3. 视觉设计系统

### 3.1 品牌与色板

- 桌面深色：`#052820`、`#062C28`、`#06382C`。
- 桌面中间层：`#0B3F34`、`#123F35`。
- 牌面：`#FFF4D8` 到 `#F2E4BD`，禁止纯白。
- 牌背：`#16704F`、`#0D5A3E`、`#0A4A3D`。
- 面板：`#031815`、`#092923`、`#0A2B24`。
- 黄铜：`#C59A58`、`#A8793A`、`#7A522C`。
- 状态朱砂：`#7A2B25`；定缺继续使用万/筒/条三套颜色和文字双重编码。

### 3.2 固定视角牌桌

- 桌面外轮廓使用上窄下宽的轻透视四边形，强度克制，避免牌面变形。
- 左右桌沿使用深黑木/皮革带，增加内侧高光、外侧暗部和旧铜压线。
- 桌面增加四家座位方向的低对比压线，让空白变成有组织的牌局空间。
- 顶部牌墙区域略暗，底部手牌区域略亮；中心公共牌区保持清晰但不出现大圆形亮斑。
- 继续保留 4%–10% 的微型蜀锦纹，背景只承担氛围。

### 3.3 玩家身份组件

每家 HUD 由以下层级组成：

1. 56–64 px 玉石头像徽章，四家使用不同纹样和字印，不依赖颜色区分。
2. 姓名与分数，保证中文字体和暗底描边。
3. 定缺徽章、庄家章、已胡章。
4. 当前行动使用头像铜环、面板边缘灯和“出牌/响应/操作”文字三重反馈。

头像徽章本轮采用原创程序化玉牌/印章，不复制参考产品人物资产；后续可无缝替换为正式角色头像纹理。

### 3.4 中央回合仪表

- 使用蜀院切角外框、四向分区和中心余牌数字。
- 当前玩家对应方向以铜金边、玉绿内光和方向文字共同高亮。
- 非当前方向保持低对比，不与弃牌竞争。
- 状态文字只显示当前最关键语义，如“本家出牌中”或“等待本家响应”。

### 3.5 牌与动作反馈

- 自家手牌继续保持手机上可读的大尺寸。
- 选中牌：抬升、铜色键线、地面阴影保持原位。
- 新摸牌：物理间隔加玉绿角标。
- AI 推荐：金玉标记；危险：朱砂底线；不使用同一种红色表达全部状态。
- 最新弃牌：铜色菱形、箭头和低幅脉冲。
- 碰/杠/胡/过：入场、悬停、按下均在 200 ms 内；动画只作用于非交互视觉层，不缩小真实触控区。

## 4. 交互与移动端合同

- 所有交互目标不小于 76×76 设计像素，重要动作不小于 108×108。
- 纯装饰全屏层必须使用 `MOUSE_FILTER_IGNORE`。
- iOS 的触摸与模拟鼠标事件继续去重，同一次触摸只能执行一次。
- 静态 HUD 位于设备 safe area 内；背景和非交互桌沿允许延伸到屏幕边缘。
- 1365×768、2048×1152、2400×1080、2556×1179 四档截图均不得出现黑边、裁切或牌面重叠。
- 减少动态效果开启时保留所有静态状态标记，停止脉冲、弹性和大幅移动。

## 5. 实施批次

### 批次 A：空间和身份

- 桌面透视结构、桌沿厚度、四家方向压线。
- 原创头像徽章和四家身份 HUD 重排。
- 中央四向回合仪表。

### 批次 B：牌局反馈

- 当前玩家头像/边缘高亮。
- 中央仪表与四家 HUD 状态同步。
- 检查选牌、最新弃牌、动作按钮与定缺反馈的一致性。

### 批次 C：响应式和触控

- 四档分辨率布局复核。
- 左上工具、动作栏、定缺和 AI 浮窗触控热区复核。
- 保证装饰层不拦截输入。

### 批次 D：构建与真机

- Godot UI 合同、C# 构建、截图矩阵。
- iOS Xcode Release、签名、安装、启动。
- 真机完成展开/缩进、三个工具按钮、选牌和一局关键流程人工验收。

## 6. 验收矩阵

| 验收项 | 合格标准 |
|---|---|
| 空间 | 桌面能辨识上窄下宽、左右厚边和四家围合，不再是纯平面绿底 |
| 牌面 | 自家牌为第一视觉权重，手机截图无需放大即可识别 |
| 身份 | 四家姓名、分数、座位、定缺、庄家、已胡和当前行动一眼可分 |
| 中央 | 余牌和当前行动方在 1 秒内可读，方向不只依赖颜色 |
| 反馈 | 选中、新摸、推荐、危险、最新弃牌状态互不混淆 |
| 触控 | 关键按钮连续触摸无漏点、无双触发、无装饰层吞事件 |
| 响应式 | 四档截图无黑边、裁切、牌面/HUD 重叠 |
| 性能 | 固定桌面装饰不使用持续重绘；动态效果可被减少动态设置关闭 |
| 规则边界 | AI、规则、计分、出牌合法性和结算逻辑零改动 |

## 7. 禁止项

- 不复制竞品头像、按钮、桌面纹理或商标。
- 不恢复大团花、大圆形亮斑、荧光绿或大面积亮金。
- 不为了塞下 HUD 缩小自家手牌和关键文字。
- 不用全屏 `Control` 默认鼠标过滤拦截牌与按钮。
- 不以桌面构建成功替代 iPhone 触控与启动验证。
