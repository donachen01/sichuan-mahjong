# 四川麻将纯 3D 牌桌改造设计方案 V1

版本：2.4.0 目标稿
日期：2026-07-18
范围：牌桌、麻将牌、牌墙、四家手牌、弃牌河、副露、灯光、相机、选牌和出牌动画；规则、AI、计分与结算数据不改写。

## 1. 产品结论

本次采用“3D 牌局世界 + 2D 原生 HUD”的成熟手游架构：桌面上所有有空间关系的对象使用真正的 3D 模型和透视相机；文字、玩家信息、AI 提示、定缺、碰/杠/胡/过、设置和结算继续使用 Godot `Control`。这里的“纯 3D”指完整牌局表现层为 3D，不把文字和触控按钮强行贴进 3D 世界。

这样既能得到牌体厚度、接触阴影、牌墙纵深、真实遮挡与统一光照，也能保留手机端清晰文字、44 pt 以上触控区、安全区适配和当前已修复的左上工具栏链路。

## 2. 设计目标

- 深墨玉绿绒面牌桌，旧铜双线桌沿，低对比蜀锦压纹。
- 暖象牙白厚牌体、深玉绿牌背、真实倒角和右下接触阴影。
- 固定浅俯视透视：本家手牌最大，上/下家视觉居中，对家不挤压中央牌河。
- 中央只保留牌河与低密度余牌仪表，不恢复复杂四向风盘。
- 选牌、摸牌、弃牌、副露都使用短促且可打断的确定性动画，不使用每张牌刚体物理。
- 规则和 AI 继续以现有 `GameState` / `GameManager` 为唯一事实源，3D 层只消费快照并发出 `tile_pressed(tile_id)`。
- iPhone 横屏优先，2048×1152 为视觉基准，同时覆盖 1365×768、2400×1080、2556×1179。

## 3. 视觉规格

### 3.1 牌桌

- 桌面主色：`#052820`、`#062C28`、`#06382C`、`#0B3F34`。
- 桌沿：深木黑 `#15110E` / `#2A2018`；金属嵌线使用旧铜 `#7A522C`、`#A8793A`、`#B99655`。
- 桌面粗糙度 0.78–0.9，避免塑料反光；旧铜粗糙度 0.32–0.46，金属度 0.72–0.9。
- 蜀锦暗纹只通过桌面材质的低强度法线/颜色变化表达，总对比不超过 7%，不使用大团花和中央圆形光斑。

### 3.2 麻将牌

- 世界尺寸：宽 0.42、长 0.58、厚 0.18；圆角半径约 0.035，倒角 3 段。
- 牌体：`#F4E9C9` / `#FFF4D8`，粗糙度 0.32–0.42；牌背为 `#0D5A3E` 到 `#16704F` 的深玉绿。
- 一套共享牌体网格；牌面使用现有万/条/筒纹理，禁止生成 108 个独立 GLB。
- 牌面纹理平面略高于牌体，避免 Z-fighting；纹理使用 mipmap 与各向异性过滤。
- 隐藏牌仅显示玉绿背面；明牌、弃牌和副露显示牌面。

### 3.3 光照

- 左上暖色主光：方向光，阴影向右下，色温约 4300–4800 K。
- 正上方柔和补光：只保证牌面符号可读，不形成中央亮斑。
- 环境色深青黑，四周通过 WorldEnvironment / 桌沿遮挡自然压暗。
- 阴影使用移动端可承受的中等图集；牌体开启投射阴影，标记和牌面纹理平面不重复投影。

## 4. 空间和相机

- 桌面有效区约 13.8 × 8.6 世界单位，中心为 `(0, 0, 0)`。
- 透视相机位于桌面本家侧上方，朝向中央；基准 FOV 38°–42°。
- 本家手牌在画面底部形成主视觉，允许轻微向镜头倾斜；上家/下家手牌沿侧轨道严格居中；对家沿上轨道居中。
- 四家弃牌河按固定起点和固定方向排列，最多展示每家 14 张；不随单行牌数重新居中跳动。
- 副露紧贴各自手牌内侧，与手牌保持独立组间距。
- 牌墙以剩余张数重建四边双层墙，仅表现总量，不改变真实摸牌顺序。

## 5. 场景架构

```text
MainSceneV2
├── GameManager                       现有规则/AI事实源
├── GameScene/Node2D
│   └── SichuanTableStage3D            直接渲染到主Viewport
│       ├── WorldEnvironment
│       ├── Camera3D
│       ├── KeyLight + FillLight
│       ├── ManufacturedClubTable
│       ├── PressedShuBrocade
│       └── GameplayTiles               牌墙/手牌/副露/弃牌按键复用
└── UILayer                           保留2D HUD/按钮/弹窗/结算
```

实作采用直接主 `Viewport` 的 `Node3D` 世界，不再套一层同分辨率 `SubViewport`。这样可减少手机上的额外显存和全屏复合开销；`UILayer/CanvasLayer` 自然在 3D 之上渲染，仍然保持原生清晰度和触控优先级。

`SichuanTableStage3D` 提供以下稳定接口：

- `render_snapshot(snapshot, all_hands, reveal_opponents, selected_tile_id, markers)`
- `set_reduced_motion(enabled)`
- `find_tile_at_screen(screen_position)` / `pick_tile(screen_position)`
- `tile_pressed(tile_id)`
- `get_visual_contract()` / `get_camera()`

3D 节点不得直接调用 AI、结算或规则函数。`MainSceneV2` 仍负责二次点击出牌、碰/杠/胡/过和错误后刷新。

## 6. 状态映射

| 数据 | 来源 | 3D 表现 |
|---|---|---|
| 本家手牌 | `get_player_hand_tiles(0)` | 全部牌面、可选中 |
| 对手手牌 | `get_player_hand_tiles(1..3)` | 明牌开关关时仅牌背，开时显示牌面 |
| 副露 | `snapshot.players[seat].melds` | 牌面朝上，按组排列 |
| 弃牌 | `snapshot.players[seat].discards` | 固定方向牌河 |
| 最新弃牌 | `recent_discard_tile_id` | 静态铜色菱形 + 轻微入场动画 |
| 新摸牌 | `human_last_draw_tile_id` / `recent_draw_seat` | 与手牌留小间隙，短促落位 |
| 余牌 | `wall_count` | 四边墙体数量与中央2D数字同步 |
| 选中牌 | `selected_tile_id` | 抬高 0.09，旧铜底光，不改触控体积 |

## 7. 交互与动画

- 选牌：120–160 ms 抬升，重复点同一张牌仍走现有出牌逻辑。
- 摸牌：160–220 ms 从牌墙方向落到手牌末端；减少动态效果时直接落位。
- 弃牌：180–260 ms 的贝塞尔/两段 Tween，从座位方向进入固定牌河格，不启用刚体。
- 碰/杠：220–300 ms 将对应牌组落入副露轨道；不阻塞规则状态推进。
- 最新弃牌标记：静态标记永远存在；允许动效时只做一次 180 ms 呼吸。
- 所有动画只影响可视 Transform，快照更新随时可以中止旧 Tween 并重建最终状态。

## 8. 手机性能预算

- 目标：目标 iPhone 横屏 60 FPS；复杂结算/弹窗允许短时下降，但不低于 30 FPS。
- 常态 Draw Calls 目标小于 180；可见 MeshInstance 目标小于 220。
- 同材质牌体与牌背使用缓存材质，牌面纹理缓存，不在每帧创建资源。
- 不启用每张牌实时物理、SSAO、体积雾、SSR 或高成本后处理。
- 3D 世界直接使用主 Viewport，避免同分辨率 SubViewport 的显存和复合开销；2D HUD 始终保持原分辨率。
- 只保留一盏投影主光；补光不投影。

## 9. Tripo / Grok 使用策略

- 核心麻将牌、桌体、桌沿和牌墙是精确工业几何，使用 Blender 脚本和 Godot 程序化材质制作，V1 预算为 **0 次 Tripo 调用 / 0 美元**。
- Tripo 只预留给未来非关键装饰，如大厅摆件、非交互铜狮或背景陈设；生成前先复用现有结果，超时必须恢复任务而不能重提。
- Grok/ImageGen 只用于未来可选的环境背景或装饰贴图；当前桌面蜀锦使用可缩放程序化材质，避免版权和分辨率问题。
- API Key 只保存在 macOS 钥匙串，不写入仓库、设计文档、日志和打包资源。

## 10. 分阶段执行

1. 工具与边界：确认 Blender、密钥、工程脏状态、现有 3D 实验和数据接口。
2. 资产基线：Blender 生成倒角牌体与桌体 GLB，Godot 导入并验证材质槽和坐标。
3. 3D 垂直切片：相机、桌面、灯光、本家手牌、牌墙和可点击选牌。
4. 完整牌局：接入四家手牌、明牌、弃牌、副露、最新弃牌、摸/打/选动画。
5. 混合 UI：隐藏旧 2D 牌体/牌河，保留玩家 HUD、动作按钮、AI 窗、定缺与结算；保留 2D 回退开关。
6. 验证：状态合同、触控、视觉截图矩阵、Godot/C# 回归、iOS 构建、真机安装与启动。

## 11. 验收标准

### 功能

- 一局中四家手牌数量、牌墙数、弃牌、副露与 `GameState` 快照一致。
- 本家牌可点击、可选中、再次点击可出牌；定缺、碰、杠、胡、过和 AI 按钮链路不受 3D 输入影响。
- 明牌开关立即切换三个对手的牌面/牌背，并保留原偏好。
- 上家和下家手牌在各自侧轨道中视觉居中。
- 结算和下一局后 3D 场景无旧牌残留。

### 视觉

- 麻将牌有真实厚度、倒角、左上高光、右下接触阴影；不存在扁平贴纸感。
- 桌面无鲜绿/荧光绿、无大团花、无中央圆形亮斑；蜀锦暗纹只做背景氛围。
- 本家牌面在 1365×768 手机等比画面仍清晰；2D HUD 不被 3D 遮挡。
- 中央信息保持低密度，牌局对象的视觉权重高于桌面装饰。

### 工程与交付

- 3D 表现层与规则/AI 解耦；旧 2D 模式可通过项目设置回退。
- 聚焦 Godot 合同测试、C# Release 构建和 `git diff --check` 通过。
- 生成四档截图并人工复核；最终 iOS App 包含最新 PCK 与 arm64 NativeAOT framework。
- 真机可安装、可启动；完整一局的手感验收必须单独记录，不用构建成功代替。

## 12. 主要风险与控制

- **移动端性能**：限制投影灯、共享材质、禁止刚体牌；通过性能合同和真机采样控制。
- **输入穿透**：3D 层只接收牌桌区域点击，2D HUD 层优先；沿用当前全局触控补偿链路。
- **状态不同步**：每次 `snapshot_changed` 以完整最终状态重建，动画不能拥有业务状态。
- **导入差异**：Blender 统一 Y-up、米制单位、应用 Transform；GLB 产物在 Godot 中做节点/尺寸合同测试。
- **大改回归**：默认保留 `ui/mahjong_3d_enabled` 回退设置，直到桌面和 iOS 两层验证全部通过。
