# 四川麻将 HUD、状态与旧功能完整性验收标准 V1

## 1. 阶段边界

本阶段只验收并修复 2D HUD、定缺选择、动作响应、已胡/点炮状态、明牌、左上工具栏和 AI 提示窗。规则、AI 决策、计分、前五阶段已通过的摄像机、3D 布局、麻将牌、桌面材质与光照参数不得改动。

UI 只能消费 `GameState` / `GameManager` 的实时快照并发送已有动作，不得在表现层伪造胡牌资格、自动跳过响应、修改结算或用超时动作掩盖状态链路故障。

## 2. 必测状态矩阵

| 状态 | 必须显示 | 必须可操作/不可操作 |
| --- | --- | --- |
| 开局定缺 | “请选择缺门”、条/筒/万三个圆印、四家 HUD | 三个合法选项均可点击；遮罩外点击不得穿透牌桌 |
| 正常牌局 | 四家 HUD、余牌、四家暗手/副露/弃牌 | 本家可出牌时仅本家手牌可点击 |
| 响应胡 | “胡”与“取消”、被响应的弃牌语义 | 两按钮均可点击，分别调用胡/过；不得漏掉取消 |
| 自摸胡 | “自摸”与“取消” | 两按钮均可点击；取消只放弃本次自摸，不伪造出牌 |
| 点炮已胡 | 获胜者手牌全部倒下明牌、获胜牌、来源箭头、已胡 HUD | 已胡手牌不可再出牌；来源箭头恰好一个并指向放铳家 |
| 明牌切换 | 三家 AI 暗手在牌背/牌面间切换 | 稳定节点必须在同一快照刷新，不允许只在重建节点时生效 |
| AI 提示 | 收起条、展开详情、透明度 0%–100% | 拖动后仍能展开/收起和拖动滑杆；透明度只影响背景 |
| 左上工具栏 | 默认缩进；展开后 AI 提示、难度、明牌、退出 | 连续触摸和 iOS 同次触摸/鼠标双事件均只执行一次且不漏触 |

## 3. 硬性量化门槛

### 3.1 定缺选择

1. 恰好 `3` 个主按钮，文字依次为“条 / 筒 / 万”，不得再出现缩小版或重复入口。
2. 设计基准下每个圆印为 `224×224 px`；在四档截图中实际可见直径不得低于短边的 `13%`，三个按钮中心间距相等，误差不超过 `4 px`。
3. 三个真实点击区均不得小于 `88×88 px`；相邻点击区不得重叠。
4. 色彩锁定为条绿、筒黄、万红；白字与深色描边对比度 `≥4.5:1`，描边 `≥2 px`。不能只靠颜色，必须同时保留文字。
5. 面板在安全区内居中，距任一安全区边缘 `≥24 px`；不得遮住本家手牌超过其高度的 `15%`。

### 3.2 HUD 与中央信息

1. 恰好 `4` 个座位 HUD，均消费 `nickname / score / ding_que / has_won / dealer / turn`；每个关键状态至少使用“文字或图形 + 色彩”双编码。
2. 左右两家姓名框中心与对应暗手列中心的屏幕垂直偏差 `≤18 px`；顶部与本家 HUD 按商业参考留在外沿身份区，不强行压到牌列中央。
3. HUD 与麻将牌投影矩形不得发生面积超过任一方 `5%` 的遮挡；四档均不得越出安全区。
4. 中央信息区只保留居中的“余牌”、数字和一行状态；方向文字“本家/对家/上家/下家”出现数必须为 `0`。

### 3.3 胡牌与点炮状态

1. `human_reaction_options.can_hu=true` 时动作栏必须同时包含 `hu` 和 `pass`，按钮文字为“胡 / 取消”；`human_can_self_hu=true` 且无响应过牌时必须显示“自摸 / 取消”。
2. 胡与取消按钮真实点击区均 `≥88×72 px`，互不重叠，且不得被透明容器截断输入。
3. 获胜者 `N` 张手牌必须 `N/N` 全部平放且明牌；可点击出牌目标必须为 `0`。
4. 点炮胡必须显示获胜牌，且来源箭头可见数恰好为 `1`；箭头保存 `winner_seat` 和 `winning_source_seat`，旋转方向与来源座位映射一致。
5. 自摸胡不得显示虚假的来源箭头；已胡 HUD 必须可见且牌局仍允许未胡玩家继续血战。

### 3.4 明牌与稳定节点刷新

1. 明牌关闭时三家 AI 暗手为牌背，开启时三家为牌面；每家数量与 `hand_count` 完全一致。
2. 同一稳定 tile node 在连续两次 `render_snapshot` 之间必须刷新 `showing_face / selected / latest_discard / recommended / danger / winning_source`，不得依赖删节点重建。
3. 连续开关明牌 `20` 次后最终状态必须与奇偶次数一致，节点总数不增长，且无重复信号连接。

### 3.5 左上工具栏与 AI 提示窗

1. 工具栏默认缩进；入口实际点击区 `≥184×76 px`。展开后 AI 提示、难度、明牌三项均 `≥184×76 px`，退出 `≥76×76 px`。
2. iOS 同一物理点击产生 touch + mouse 双事件时只执行一次；连续独立触摸 `20` 轮必须 `20/20` 生效。
3. AI 提示窗只允许标题拖动；展开按钮、透明度滑杆和推荐按钮不得触发拖动。
4. 拖动到四个边界角后，展开/收起各 `5` 次、透明度 `0/25/50/75/100%` 各一次，状态必须全部正确；0% 时文字仍保持不透明并有可读暗底/描边。
5. 收起尺寸 `560×76`，展开尺寸 `760×264`；四档下均不得越出安全区或永久遮住本家可点击手牌。

### 3.6 跨分辨率与视觉层级

1. `2556×1179`、`2400×1080`、`2048×1152`、`1365×768` 至少覆盖定缺、正常响应、点炮已胡、AI 展开四种状态，共 `16` 张真实渲染图。
2. `16/16` 均不得有黑边、透明洞、HUD 越界、文字裁切、按钮重叠或遮住本家出牌区。
3. 视觉权重必须保持：本家手牌/响应按钮 > 中央牌局信息 > HUD > 工具栏/装饰；定缺和响应为模态例外。

## 4. 功能回归门槛

以下真实链路全部通过才可放行：定缺选择、响应胡/过、自摸胡/取消、碰/杠/过、已胡继续血战、结算、明牌动态刷新、工具栏事件去重、AI 浮窗拖动/透明度、3D 点击映射、C# 四川规则合同。任何测试即使退出码为 0，只要输出含 `SCRIPT ERROR`、`Parse Error` 或未出现成功标记，仍算失败。

## 5. 双设计师评分

主设计师与独立设计师分别按 5 项评分：

1. 定缺与动作按钮的成熟度、清晰度和触控可信度；
2. 四家 HUD 的信息层级、对齐与桌面融合；
3. 胡牌、点炮来源和明牌状态的一眼可懂程度；
4. AI 提示窗、左上工具栏与牌局空间的冲突控制；
5. 四状态、四分辨率的一致性与商业完成度。

通过条件：双方均 `≥23/25`，每项 `≥4/5`，`P0=0`、`P1=0`，第 3、4 节全部通过。

漏显示胡/取消、已胡手牌仍可打、来源箭头错误、定缺或工具按钮偶发失效、明牌状态不刷新、旧功能被新 UI 丢弃均为 P0/P1，必须重做；纯装饰偏好可列 P2。
