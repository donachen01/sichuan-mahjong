# 内江麻将 UI 基准包

本文档把用户提供的两张目标截图沉淀成项目 UI 基准。它不是最终设计稿，而是后续改 Godot UI 时共同讨论、验收和防止跑偏的依据。

## 目标方向

目标不是做“信息面板型桌面工具”，而是做“启动页同源的逼真 3D 卡通 Mahjong App”：

- 牌更大，字更大，优先保证手机上 1 秒内看清牌、分、动作。
- 桌面中心留给牌局，不用大量说明性卡片占空间。
- 操作按钮巨大、靠近右下拇指区，按钮含义一眼识别。
- 结算页以输赢和牌型为主，不把信息拆成过多小卡。
- 视觉基调向启动页靠拢：温暖木质房间、圆润 3D 卡通角色、厚实立体麻将牌、柔和日光、高光和投影。

## 启动页风格基准

用户希望整个 App UI 与启动页保持同一套视觉语言。启动页的核心不是扁平棋牌界面，而是“真实材质 + 卡通比例 + 软萌 3D 渲染”：

- 场景：温暖室内、木地板、木桌、木椅、窗边暖光。
- 材质：木头有圆角和高光，牌桌是厚实木框 + 绿色绒布。
- 麻将牌：圆角厚牌，白色/象牙色牌面，绿色侧边，柔和阴影。
- 角色：可爱动物/玩偶式 3D 角色，圆润、大眼、低攻击性。
- 光照：暖色主光，柔和环境光，阴影清楚但不脏。
- 字体：标题和大按钮应有卡通立体感，奶油黄/橙色描边/投影。
- 情绪：轻松、亲切、可爱，不是赌场风，也不是硬核工具风。

### 启动页风格关键词

`逼真 3D 卡通`、`温暖木质`、`圆润厚牌`、`软萌角色`、`暖光`、`高饱和但柔和`、`大字号卡通描边`、`低复杂度高可读`

## 参考图 1：牌桌页基准

用户目标截图尺寸约为 `2048x1152`，横屏比例 `16:9`。它提供的是“清晰手机棋牌布局”的信息密度基准；视觉风格则要融合启动页的 3D 卡通质感。关键观察：

- 自家手牌牌面约 `105-115px` 宽、`155-170px` 高，占屏幕高度约 `14%`。
- 自家手牌贴近底部，牌面可读性高，牌与牌之间几乎无缝但不拥挤。
- 中央出牌区牌较大，最近打出的牌和“胡/过”按钮非常醒目。
- 右下动作按钮是圆形大按钮，直径约 `120-150px`，颜色强烈。
- 玩家信息贴四边，不占中心牌桌；头像、分数、身份标签较大。
- 顶部信息简洁：房号/局数/时间/网络，不把调试信息放在主桌面。
- 背景可以保留深绿色桌布的清晰对比，但桌框、按钮、弹窗应向启动页的温暖木质和圆润 3D 高光靠拢。

### 牌桌页目标规格

| 区域 | 目标规格 |
|---|---|
| 设计基准 | 横屏 `2048x1152`，同时适配 `1920x1080`、`1600x900`、`1365x768` |
| 自家手牌 | 基准牌面 `108x162` 左右，最低不小于 `96x144` |
| 中央弃牌/展示牌 | 基准牌面 `64-78%` 自家手牌大小 |
| 对家/左右手牌背 | 可读轮廓优先，允许比自家小，但不应小到条筒字形糊成一团 |
| 操作按钮 | 主动作 `胡` 直径 `136-156`；次动作 `碰/杠/过` 直径 `108-132` |
| 文本字号 | 关键分数 `34-48`；玩家名 `24-30`；局数/状态 `26-34` |
| 安全边距 | 横屏手机四周 `24-36px`，避开圆角和系统手势区 |
| 信息密度 | 正常打牌时不显示长句说明，不显示大面积统计卡片 |

### 当前实现差距

当前项目里与该目标直接相关的尺寸：

- `scripts/ui/HandCanvas2D.gd`：自家手牌 `TILE_FACE_SIZE = Vector2(92, 138)`，比目标偏小。
- `scenes/ui/MahjongTile.tscn`：基础控件 `95x135`，可作为小牌/副露牌，但自家主牌应更大。
- `scenes/table/MainSceneV2.tscn`：中心区域有 `CenterStatsCard`、`CenterHintCard`、`CenterMeldCard`、`CenterDiscardCard`，更像调试/桌面面板，占用了牌桌空间。
- `scripts/game/MainSceneV2.gd`：动作按钮目前 `胡 128x90`、`碰 92x74`、`过 78x66`，目标应更接近圆形大按钮。
- 左右 rail 目前 `304/320px`，适合信息面板，但会压缩中心桌面。

### 牌桌页改造原则

- 优先放大牌，不优先增加说明文字。
- 自家手牌是第一视觉层级，动作按钮是第二层级，最近出牌是第三层级。
- 把“调试/建议/统计”收进浮层或小图标，不常驻占桌面。
- 玩家信息用头像卡贴边显示，不用大块列表式卡片。
- 出牌区、碰杠牌、胡牌标记必须服务于“看清楚当前局面”。

## 参考图 2：结算页布局基准

目标截图是大型浮层结算，背景牌桌变暗，结算主体占屏幕大部分。它提供的是“结算信息怎么放大和排序”的布局基准；最终视觉不应是生硬红色扁平面板，而应转译成启动页同源的 3D 卡通结算面板。关键观察：

- 弹窗宽约屏幕 `82%`，高约 `68-72%`。
- 左侧是玩家列表，选中玩家用浅金高亮，分数非常大。
- 右侧顶部是赢家/输家关系和总分，字号极大。
- 中间显示整手牌，牌型牌面清晰。
- 明细只有关键行：来源、对象、倍数/番数、得分。
- 底部按钮巨大，颜色明确：返回、继续等。

### 结算页目标规格

| 区域 | 目标规格 |
|---|---|
| 遮罩 | 背景暗化 `55-70%`，仍能看出桌面上下文 |
| 主面板 | 宽 `80-86vw`，高 `66-74vh`，居中 |
| 左侧玩家栏 | 宽约主面板 `22-26%`，头像 `96-130px`，分数 `44-60px` |
| 右侧顶部结果 | 红色/金色主视觉，牌型和得分 `56-72px` |
| 手牌展示 | 单行优先，牌面 `58-72px` 宽；牌多时压缩间距不压缩到不可读 |
| 明细区 | 米黄色底，文字 `30-38px`，一行一条结算 |
| 底部按钮 | 高 `78-96px`，宽 `220-320px`，文字 `36-46px` |

### 当前实现差距

当前项目结算页：

- `SettlementPanel` 为 `1160x760`，在 `2048x1152` 上仅约 `57%` 屏宽，目标应扩大到约 `80%+`。
- 视觉风格是深绿金边卡片，信息被拆成“本局最佳/手牌/分数明细”等多卡，清晰但不够像手机棋牌结算。
- 玩家列表宽 `292px`，头像和分数不够大。
- 顶部结算结果 `SettlementHeroCard` 高 `96px`，目标应更像 `160-220px` 的红色主结果带。
- `NextRoundButton` 为 `168x52`，目标应提升到 `260x84` 级别。

### 结算页改造原则

- 结果先行：先看谁赢/谁输/多少分，再看牌型明细。
- “牌型 + 番/倍 + 得分”必须是右上主视觉。
- 左侧玩家栏只显示头像、方位、昵称、总分变化，不塞规则解释。
- 明细区不要表格化过重，采用大行距结算条。
- 结算牌面不应小于弃牌区牌面。

## 颜色、材质和视觉基调

推荐主题名：`温暖 3D 卡通麻将风`

| 用途 | 建议 |
|---|---|
| 主背景 | 暖木色房间/桌面环境，局内可简化为木框牌桌 + 绿色绒布 |
| 桌布 | 清晰深绿 `#0B6A48` 附近，带细腻绒布纹理 |
| 木质 | 蜂蜜木色、橙棕阴影，圆角厚边，高光明显 |
| 牌面 | 暖白/象牙白 `#F8F1DE`，绿色侧边，圆角，投影清楚 |
| 主按钮 胡 | 橙红/金黄渐变，球形或厚按钮，高光和外发光 |
| 次按钮 过 | 亮绿果冻感，球形或厚按钮，高光和投影 |
| 结算主面板 | 木框 + 奶油黄内容区 + 暖红/橙金结果区 |
| 文字 | 关键文字用奶油黄/白色，橙棕描边，厚重卡通投影 |
| 辅助信息 | 半透明深绿/木色小牌匾，不抢牌面 |

## 3D 卡通 UI 转译规则

Godot 里不一定所有控件都真做 3D，但视觉上要模拟 3D 卡通：

- 所有主要面板使用厚边、圆角、内高光、外投影。
- 按钮不要像普通扁平矩形，要像“可按下的圆润道具”。
- 麻将牌要有厚度感：牌面、侧边、底部阴影分层。
- 弹窗像木框牌匾或桌面托盘，不像系统对话框。
- 分数和牌型标签像启动页标题：大、厚、亮、有描边。
- 角色/头像区域未来可加入启动页同款软萌动物头像或 3D 卡通头像。
- 不使用冷硬科技风、赌场霓虹风、扁平后台风。

## 字体和可读性

- 手机横屏最低目标字号：普通正文 `26px`，明细 `30px`，按钮 `36px`。
- 所有关键分数必须有描边或阴影，避免压在复杂背景上发虚。
- 不使用细字重显示关键数字。
- 牌面图案优先使用图片资源，不依赖小号文字描述。
- 标题、胜负、番/分可以使用更圆润更卡通的字形和描边，接近启动页标题气质。

## 验收标准

每次 UI 改动必须至少检查：

- `2048x1152` 横屏：牌、按钮、结算信息完整无遮挡。
- `1365x768` 横屏：文字不溢出，动作按钮不挡手牌。
- 自家手牌 14 张时全部可见，最后摸牌有明显间隔。
- 结算页一眼能看出赢家、牌型、番/分、得失分。
- 不出现“按钮亮但实际触控区域很小”的问题。
- 背景装饰不得降低牌面和文字可读性。
