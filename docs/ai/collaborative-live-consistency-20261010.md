# 共同判牌接入真实游戏：2026-10-10

本轮已修改游戏共享的 C# 决策能力，并验证 Godot 游戏中的实际选择和落牌。《四川麻将技术论（下部）》5-8：摸4条打7条，摸3条打3条。第二批六手参考方向也已一致。补查并修复了3-17 D中“3筒已杠完，拆45筒”的实际选择。

用户明确要求处理纸面判别与游戏出牌不一致的问题，并指出5-8的两种摸牌及此前已发现的两个缺口。本轮未使用“四川麻将视频深度学习”技能。以下检查只服务于本次修改，不成为固定回归清单，不加入默认测试、CI或定时任务。

原有20条用户判断/纠错及其前提保持不变；P01–P06仍保留原提案与反馈范围，不因算法采用教材参考方向而自动新增用户认可记录。历史讨论中的“当轮未修改生产代码”仍是当时的事实；本文件记录后续实现阶段。

主要修复包括：

- 改良计算增加逐听口番值、合法弃牌和副本检查。保留全部原听口且各听口番值不下降时，允许计入部分听口加番；同一摸牌事件不重复计数。5-8弃7条后，未来摸3条弃6条或摸6条弃3条，仍听6筒/9筒，其中9筒可转为七对。进张为零的听口不产生收益。
- 普通胡与七对分别计算距离。五组理牌纳入将牌占位、已成刻子、复合搭子、搭子超载及公开供碰条件；弃牌后的分组必须支持实际计算出的普通上听数。
- 根据公开副本修正搭子质量。两面的一端被杠完或严重耗尽时，不能继续按完整两面评价；生张对子与后对、均匀定缺与两家缺同门也分别处理。供碰系数是教材启发的结构指标，不是额外实体牌或精确概率。
- 区分“一摸一弃即可改良当前搭子”和“保留候补，以后替换整组弱搭”。这修复了过度估计候补、提前拆开57789条的错误，同时保留3-20 C中5筒候补替换24条的机会。
- 有足够本家摸牌机会、存在孤张发展渠道时，允许拆补成枯竭的弱边搭，明确承担普通上听退一步的代价；已经听牌、临近流局、明显防守或更高优先级的整局计划受保护。牌墙、暗牌数量与公开副本不一致的局面不使用此时间判断。
- 普通和轻量入口调用同一能力；最终建议进入原有合法性、安全和策略裁决。CLI补齐阶段、巡次、已胡分值和摸杠来源字段。CLI仍是单独快照计算，真实游戏另由持久牌手代理验证。

验收结果：

- 22个条件局面，普通、轻量及移动端精简接口各验证一次，共66次真实游戏决策与落牌。全部建议都映射到当前实体手牌，并由实际出牌函数打入牌河。
- 5-8两手各追加三种模式的连续摸打：先以原13张手牌建立牌手策略，再由游戏真实摸牌流程摸入4条或3条，保留已有代理与策略记忆后决策、落牌。另6次全部通过，合计72次实际游戏验证。
- 22个局面进行6种花色互换、牌序镜像及普通/轻量对照，共528次通过。它们是同一批局面的变换检查，不是528个独立实战样本。
- 逐听口加番、枯竭听口、未清缺门及进张事件不重复计数的聚焦检查通过。现有孤张和木桶两个相关单项测试通过；旧“3-15 C打9条即失败”断言已改为有时间/仅一摸的条件对照。旧测试中的不完整公开局面仍不得捏造后续时间。
- 当前Godot程序集、Release CLI和相关单项测试均构建成功。当前机器的72次游戏决策段最大记录为365毫秒；这是本批局面观测，不是整局性能保证，也不代表手机性能。

游戏验证使用明确补全公开条件的合成局面。每个局面核对牌墙、各家暗牌、副露和牌河合计108张、实体ID不重复，且游戏桥接后的手牌、公开牌、剩余上界、定缺、暗牌张数、牌墙和阶段与输入一致。补全的公开损耗属于本次验证假设，没有将用户未提供的信息登记为“已确认零张”。对手暗牌与实际牌墙身份不传入C#公开信息决策。

验证过程中曾发现整数/小数编号比较错误，以及未将通用数组正确赋给游戏实体牌墙的问题；均修正验证程序并重新运行。最终结果中的72次全部来自修正后的完整实体局面。

最强交付证据为当前桌面Godot真实C#运行时及实际游戏执行链。移动端精简接口是在桌面调用同一接口验证，本轮没有重导出iOS NativeAOT、安装手机包或验证真机。已有独立安装包或已经运行的进程不会因源码修改自动更新；应使用重新构建并启动的当前工程。此次验证证明所列前提下的出牌一致性，不宣称已经证明整局收益提高或吃透全部教材。
