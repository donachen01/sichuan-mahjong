# 碰牌改善与持续贪自摸：本轮实现（2026-10-01）

本轮按用户确认方案修改 C# 实际决策和后续模拟，不改四川结算规则。没有打包或安装 iOS。

## 碰牌

`SichuanDevelopmentPolicy` 使用本家手牌、各家公开副露/定缺/出张和公开剩余数量比较“不碰”与“碰后实际舍牌”。

- 下降上听数仍是改善，但不再是模拟自动碰牌的必要条件。
- 同上听数的有效进张供给改善可以通过，包括转向三个对手都缺的独占花色。
- 后续补杠按本家获得第四张的机会计算，不能把对手打出第四张算作补杠。已经留在本家手里的第四张也纳入；模拟能用既有第四张补杠，不局限于刚摸到的牌。
- 补杠可以补偿有限的听口损失，而非强制要求原始进张数不减。死张不给补杠价值；大的结构损失仍需拒绝。
- 安全且时间充足的独占花色局面，允许上听数暂退一阶：枚举下一张有效进张、合法舍牌和恢复听牌路径，以有限摸牌次数估计改善。不是任意牌都能拆听。
- 实际出牌使用同一个改善选择器，只有候选舍牌危险不高于原选择时才替换。碰牌反事实先调用真实出牌引擎，保证预定首打与执行首打一致。
- 主决策仍综合原有反事实收益、路线损失和首打风险；新增条件并不强制碰牌。

## 胡与过

真实反应的根节点仍比较立即胡与过/碰/杠的整局净分。采用相同牌局样本的成对比较、独立确认样本及统计余量，不因经验规则允许就直接过胡。

后续模拟每次遇到可接炮的机会，会用当前可见信息重估发展计划，而不再一律接胡：

- 目标、独占花色、未见听张、已确认拒胡次数、拒胡上限、危险等级、杠是否兑现、自摸估计和活杠机会进入个人计划。
- 睡宽床普通听牌：5 张以上无危险可持续等待，一般危险最多 2 次；3—4 张无危险可继续，一般危险接胡；2 张默认接胡，有具体改善或活暗刻例外。
- 使用小结的 3—4 张一般危险立即胡作为默认；不把牌例 4-5 A 中更宽松的“一般危险过一次”悄悄混入。
- 已兑现一杠时收紧等待额度，重大危险、机会不足或发展失效时收手。
- 三家分别缺一门继续使用上一节独立规则，不把它的第八巡限制套在睡宽床上。
- 已成清一色、七对、大对子、金钩钓不套用普通平胡小结；有价值的手牌仍需要收益确认。
- 自摸仍兑现，抢杠/杠后炮在轻量后续策略中兑现其特殊收益；本轮“贪自摸”主要改变接炮选择。

后续策略是有界近似，不在每个节点递归展开完整蒙特卡洛。它以公开供给、剩余摸牌次数、动态付款人数及风险折让判断继续是否值得；最终根节点仍用完整终局模拟估计放炮、他家自摸、杠/呼叫转移和流局结算成本。0.005 供给改善门槛、0.15 杠机会、0.10 重建优势及风险折让是工程保守参数，不是书中的定理或经实战校准的概率。

## 事件、记忆和公平边界

各座位独立维护自己的已确认拒胡事件。查询不花额度，换听不重置额度，检查点重建保留额度，新局重新建立。`AgentPlan.DevelopmentPlan` 提供当前可检查的计划；已有普通、七对和清一色路线继续由原有结构维护。

模拟的策略视图只给该座位自己的假想手牌、公开手牌张数与公开历史，不提供其他假想手牌内容和未来牌墙。每次摸打、副露都会更新视图。主动过胡的锁在自己摸牌时解除；选择碰/杠放弃胡牌仍计入机会使用，但不额外制造“过”动作的顺胡锁。

公开清缺证据只在等待状态排除缺门花色；不能因刚声明定缺就把牌全放进牌墙。

## 本次验证及边界

本次选取的验证是针对这些变更的场景，不构成固定回归清单：

- 新增 `--development-policy`：宽/窄听口、同距离供给改善、活/死第四张、杠兑现、危险升级、个人计划和检查点、真实碰后首打一致性、完整模拟持续过胡。
- 原有 `--hu-income-cost`：真实结算、顺胡/摸牌解锁、公开信息隔离、根节点收益比较。
- 原有 `--distinct-dingque-hu`：上一节额度、危险、巡数和真实选择行为。
- Godot .NET 实际运行接口：同一个睡宽床牌例经完整 JSON 与紧凑接口均选择 pass，且经过整局收益比较。

证据位于 `evidence/development_policy_20261001/`。专用 32 样本牌例实际出现了后续主动拒胡（不是只在根节点过一次）。

牌例 4-6 被纳入估算，但本轮保守模型在该测试公开状态下仍选择接胡；没有把原文“必然能碰/任意筒子可拆听”硬编码为命令。这是具体状态的评估结果，不表示该牌例必然最优接胡。

验证证明行为接线、边界和指定场景成立，不等于已通过大规模对战证明整体胜率上升，也不代表 iPhone 性能或 NativeAOT 真机验证完成。
