# 《四川麻将技术论》3.5 上、下：搭子木桶理论与 AI 应用

来源：`/Volumes/other/四川麻将读牌资料/文字/四川麻将技术论（上部）.pdf`，PDF 物理页 72–80。下述内容区分原书结论、可计算的推论和当前工程状态。原书牌例仅给出局部公开信息，并非完整牌谱；不可把参考答案当作所有对局状态的绝对标签。

## 一、读懂原理

三上听以内，普通型手牌的速度不只看所有有效牌相加，还取决于必须完成的最弱要素。若整手牌已有四个强要素，却有一个关键搭子只剩一张进张，继续美化强搭子通常不能解决成叫瓶颈。原书牌例 3-16 的 89筒只靠 7筒完成边张，7筒现三张，因而应考虑直接进张、通过 8/9筒补强、或建立替代搭子后拆掉 89筒。

“最弱”必须动态计算。牌例 3-17 A 的 23筒两面、57条坎张、89筒边张按可完成的余张与改良比较，应拆 89筒；B 自家碰出 666条，57条的 6条只剩一张，应拆 57条；C 两组坎张完成张数相同，但碰出 666筒使 35筒的改良更差，应拆 35筒；D 杠出 3333筒后，45筒名义上是两面，实际只剩 6筒可进，和 57条同为四张完成张时，后者的改良更好，故可拆名义两面。固定的“两面优于坎张”只适合公开损耗相近的早期先验。

复合搭子有两面：例如 223、668、899、135 的多路线会增大接牌机会，但它也占据额外手牌位置。牌例 3-18 说明对子现张会让原来可保留的“后对”变脆弱，候选舍牌可随单张 9万被看见而从 8万改为 2条。原书对该例各搭子有效张的图表属于特定拆分，不等于每张牌有一份可相加的独立进张。

下篇有两条更深的限制。其一，一上听不能机械拿局部最弱搭子作唯一依据：3-20 A 打 8筒后虽似乎改善短搭，却使下一摸能听牌的路线几乎只剩 1筒；必须逐个模拟“摸牌→最佳弃牌→实际听口”。其二，四面子一将的普通和牌最多需要五个有效要素，已经碰出的面子占其中一组。3-21 有一组副露与五组暗手要素，须早点处理超载；3-22 的 2+2+2+4 与 2+2+3+3 表面同为四个暗手要素，但四张挤在同一复合搭子会让其他搭子的后续改良被迫拆掉。因此“数量”和“进张后的结构存活率”都要算。

## 二、逐例转为可检验的能力

| 原书牌例 | 关键变化 | 应测的算法能力 |
| --- | --- | --- |
| 3-16 | 89筒的 7筒现三张 | 识别低余张的必要搭子；比较补强和替换路线，而不只看名义边张 |
| 3-17 A/B | 57条的 6条从可用四张变成只余一张 | 公开副露/自家副露进入每个搭子的动态有效张；同一手牌因公开证据翻转选择 |
| 3-17 C/D | 完成张相同，改良张不同；名义两面被自杠封死一侧 | 按“完成机会→改良机会”比较，不能按搭子名称直接排序 |
| 3-18 | 9万多见一张 | 对子可碰机会、后对的脆弱性与替代两面同时参与评估 |
| 3-19 A/B | 刻子＋多一张的四张结构 | 在未听牌时计算那一张的边际价值，避免把四张整体重复加分 |
| 3-20 A | 一上听局部拆弱导致听牌入口骤减 | 用合法的下一摸及最佳弃牌枚举成叫路径，而不是局部木桶分 |
| 3-20 B | 两家缺筒使 88筒的碰出机会变化 | 对子进张须区分墙内自摸和别人可打、且实际允许碰的机会；不能把定缺直接等同必出牌 |
| 3-20 C | 保留看似多余的 5筒作为 24条的候补 | 对候补张赋予“未来替换短板”的选择权价值；不能只删当前未入块的牌 |
| 3-20 D | 6筒严重损耗，保留条子一门的调整空间 | 在互斥拆分间比较最弱组与后续替换路线。书中题面只标 6筒见三张，解析又提 3/6筒各见三张；复原用例须分别测试这两个公开状态 |
| 3-21 | 一组已碰出，暗手有五组待发展 | 将副露算入五要素容量，找出超载组并比较现在拆与将来被迫拆的损失 |
| 3-22 A/B | 2+2+2+4 对比 2+2+3+3；四连坎 | 检查进张后的结构存活率，不能仅靠总有效张或机械惩罚四张连体 |

## 三、当前工程已有和缺失的部分

- `SichuanShantenEngine`、`SichuanExactHandAnalyzer`、`SichuanUkeireEngine` 已能计算向听与严格活进张；这是木桶判断的上层约束。`SichuanWallAvailabilityEngine` 已把公开未见张进一步转换为牌墙预期，不能把所有未见张都当作可自摸张。
- `SichuanHandShapeEngine` 已搜索互斥拆分，保留好搭/坏搭、对子压力、搭子溢出、同向听改良等指标。但当前主要以静态的两面/坎张/边张权重给每个拆分打分，没有显式记录每个必要搭子的完成余量、改良余量和最弱值；只保留若干静态高分拆分，也可能漏掉公开损耗后更好的拆法。
- `SichuanHandImprovementEngine` 可枚举同向听且提升严格活进张的下一摸；目前它只向牌形摘要提供合计张数，不能说明“哪一组短板被替换”以及别的组是否被迫拆解。
- `SichuanLimitedLookaheadEngine` 会枚举一摸一弃后的向听/活进张，但平均分不足以表达窄听口尾部和复合搭子的结构存活率，且采用整数代表墙而非完整预期分布。
- `SichuanTwoPlyReadyEvaluator` 已有一上听逐进张、再弃牌、再算听口的能力；它只在若干实验性策略变体里参与决策。代码已记录一副露牌谱上盲目扩大覆盖产生的回退，因此不能因为书里 3-20 A 就直接全局启用。
- 普通型、七对、清一色的路线评估已存在，木桶诊断只应在普通型可达路线内解释；七对的“七组对子”不能受到“五搭子超载”惩罚。防守、追分、查叫净值也不能让位给一个局部牌形分。

## 四、建议的正式算法

1. **候选与信息边界**：只用本家手牌、自家副露、公开现张、三家定缺、已知过牌/碰杠与公平的牌墙/对手出张估计。由每个 AI 自己的局内记忆生成其可见状态；共享数学算法，不共享暗手。先过定缺、合法动作和路线可达性，再求当前出牌后的普通型/七对/清一色距离。
2. **互斥五要素拆分**：普通型对每个合法弃牌枚举互斥拆分，包括已完成面子、将牌候选、两面/坎张/边张/对子及未入组张。所有拆分须达到该候选的最优普通型向听；已副露的每一组先占一个面子位置。对每个拆分明确选哪一对为将，其他对子才可能是待碰面子。统计必要要素、超载要素和四张以上复合结构的被迫拆解率，而非按同张叠搭重复计数。
3. **动态短板值**：每个必要未完成要素分别列出完成张及预计可达质量（墙内自摸、合法碰的机会分开），再列出不降向听且能提高该要素可达性的改良张。同一张若同时改良两组，计算整手方案的并集与条件后续，不能把两组各记满一次。拆分的短板值取必要未完成要素中的最小值；一手牌在同向听拆分中选择最有希望且次弱组也稳定的拆分。
4. **替换与超载的前瞻**：对有争议的候选枚举下一次本家摸牌及最佳合法弃牌，记录：降向听概率/质量、仍保持当前向听但严格活进张变宽的质量、进张后原五要素保留比例、被迫立即拆另一个有效搭子的质量。3-20 C 的候补 5筒、3-21 的超载、3-22 的四张挤占，都应由这些真实后续差异体现；不要为特定牌谱设置牌值或固定弃牌。
5. **决策门槛**：木桶量先作为候选解释与同向听、近活进张、近净值时的决胜证据。一上听优先使用逐摸后真实听口的两步证据；若短板替换要求牺牲当前一阶速度，只有后续搜索/收益有明确优势时才允许翻案。防守/追分模式仍按各自的净值与风险目标裁决。

建议输出可审计字段：`ordinary_bottleneck_block`（类型、牌及活完成张）、`improvement_mass`、`replacement_mass`、`capacity_overflow`、`forced_break_mass`、`ready_entry_mass`、`worst_ready_wait_mass`、`decomposition_route`。这些是策略证据，不能标成“胡牌概率”；没有足够完整牌墙/出张信息时应保留不确定性。

## 五、落地顺序与验收

先用 3-16 至 3-22 构造**公开信息边界明确**的牌例状态，并增加去掉/增加一张现张、花色轮换、将牌位置变化、副露数量变化、七对/清一色可达等对照；仅检验章节主张能否在条件成立时翻转，不把原书答案硬编码为弃牌。然后在正式 AI 候选上计算只读木桶指标，记录当前决策和新指标的分歧；对分歧运行相同公开状态、相同随机种子的短程对照，比较成叫率、和牌/净分、查叫损失、放铳与决策耗时。只有在分层样本中收益稳定且没有破坏公平信息边界，才把指标从诊断升级为有限裁决。

## 六、第一阶段代码落地（历史记录，当前实现见第七节）

新增 `SichuanBucketTheoryEngine`：在候选弃牌后的普通型手牌里枚举互斥拆分，只比较达到最优普通型向听的拆分；选定将牌后按墙内预期余张计算每组完成机会，并对同机会的搭子计算通过后续摸牌获得的改良机会。它保留最弱、次弱及改良量，同时从所有同向听拆分中识别最多可能存在的第六组要素。该字段表示结构压力，不是强制拆牌指令。

正式决策只在公开信息、缺门已清、普通型二上听、非已承诺清一色、非防守/追分且牌墙仍有空间时调用；为减少手机端计算量，先完成原有决策，再只对当前选项与最多三个近值候选算木桶。候选必须不倒退向听，活进张最多低一张（牌墙预期转整数时的窄幅容差），统一动作净值与出牌风险也受保护；木桶证据明显占优时才可替换。`bucket_disabled` 是同状态对照开关，不是另一套玩法规则。

聚焦核对覆盖 3-17 A/B/D 的公开耗牌翻转、3-21 副露后的第六组、3-22 A 的拥挤结构，以及七对边界。3-16 的合成公开状态中，旧决策打 6条，新决策在同向听、活进张最多差一张的约束下拆 89筒；这证明机制进入了正式出牌链。3-20 A/C 的合成状态里原有正式 AI 已分别打 3筒、8筒，保留这两项针对性对照。3-20 D 的局部木桶值能发现拆 45筒有更多改良，但正式 AI 仍打 9条；当前两方案的直接活进张相差两张，尚无足够的整手后续收益证据可跨越保护门槛。`dotnet run -c Release --project dotnet/AI.Core.Smoke/AI.Core.Smoke.csproj -- --bucket-3-5` 为本节聚焦验证；上一节 `--isolated-3-4` 也已复核。

仍未完成的是一上听的全局两步听口比较、对子受其他人定缺影响的合法碰牌出张模型，以及 3-20 C 候补张/3-22 四张复合搭子的条件长期收益。现有木桶值不会越过这些证据边界，也不会仅凭局部牌例改写七对、清一色、防守、结算或 iOS 构建。iOS 本轮未打包。

## 七、完整机制接入：公开信息下的后续收益确认

本轮替换了第一阶段的“活进张最多少一张、静态净值接近才允许比较”门槛。`SichuanBucketContinuationSelector` 在一上听和二上听都可工作；发生短板、替换空间、容量或对子供牌冲突时，所有同向听且满足当前风险边界的候选都进入相同公开样本的后续比较。不会因为即时活进张少两张而把 3-20 D 的打 4筒排除在计算外。原有防守、追分、已承诺清一色和尾盘专用策略保持各自职责。

各项理论的算法归属：

| 理论能力 | 当前执行方式 |
| --- | --- |
| 动态最弱/次弱搭子、现张损耗 | 互斥结构枚举与公开牌墙余量；改良集合取并集，避免一张牌在多组重复计数 |
| 五要素容量、四张复合组挤占 | 结构压力提出比较需求；逐次摸牌/碰牌后的重新舍牌真实消耗余张与调整空间，最终收益评价被迫拆搭的代价 |
| 候补张补强或替换短板 | 初始弃牌后模拟整段剩余牌局，每次自身摸牌、碰杠后都重新计算合法舍牌；不固定原来的搭子划分 |
| 对手定缺与碰牌供给 | 从公开历史、定缺、可见牌、各家暗牌数量中采样守恒的未知牌分配；模拟对手按自身定缺清牌，实际发生合法碰牌才记收益，不给对子添加固定定缺奖励 |
| 一上听不能盲目拆弱 | 每次模拟进张后重新计算实际和牌/听牌结构及后续摸打，不用局部木桶值代替整手听口 |
| 即时进张与后续收益取舍 | 同一批未知牌与牌墙排列配对比较完整剩余牌局的胡牌、杠分、血战和查叫净分；活进张下降本身不再禁止提案 |

每次冲突先用 32 个公开信息样本筛选全部合格候选；若发现正收益方案，再用互不重叠种子的 96 个样本单独确认该方案与原方案。必须有效样本数足够、净分差超过 `max(0.10, 2.4×标准误)`，且初始放铳概率不明显增加，才替换正式出牌。无明确优势时维持原方案，这是已经完成计算后的不确定性裁决，不是遗漏策略。候选、样本数量、有效样本量、净分、碰牌次数和标准误通过 CLI 与 Godot C# 接口输出，便于逐局复盘。

模拟器使用每次调用独有的向听缓存和公开状态舍牌缓存，不跨智能体保存未知牌。加速版本与原版本在相同样本上的结果必须一致。算法不读取实际对手暗手或未来牌墙；运行时隐藏摸牌事件、隐藏听牌标记不会进入公开采样边界。真实公开状态必须满足四张守恒、暗牌数量与墙数一致、弃牌/副露历史完整；不满足时返回明确状态，保留现有合法决策，不捏造牌局补全。

### 本轮证据与精度边界

- 章节结构测试覆盖 3-17 A/B/D、3-20 A/C/D 的结构证据、3-21、3-22 与七对边界。
- 新的完整链路测试建立了包含真实弃牌归属与正确墙数的 3-20 D 合成公开状态；打 4筒已进入正式候选推演，既不会被一张进张门槛阻挡，也不会因为牌例参考答案而被强制选中。
- 控制世界验证：相同对手手牌，缺筒时强制打出 8筒并使本家合法碰牌；改成缺条后该次碰牌供给消失。只在测试内部注入控制世界，生产入口不接受对手真手牌。
- 对相同公开样本，加速/原始推演的候选净分和碰牌计数一致；加入隐藏摸牌事件、修改运行时隐藏听牌标记不改变结果。
- 早先第一阶段的 3-16 合成状态没有完整弃牌归属、暗牌数量/墙数也不一致，因此旧的“它改打了 9筒”只能证明当时的局部规则生效，不能作为完整收益证据。本轮将其改为不完整状态不得触发完整推演改判的边界测试，历史结果保留在第六节。

这里的“完整”指两节中的结构、替换、容量、供牌和后续收益机制均进入正式路径，并非穷尽所有真实世界或证明全局最优。未知牌采样、对手模拟策略和有限样本仍是模型近似；某个原书答案不被选中时，应查看公开状态假设及配对收益证据。iOS 本轮仍未打包、安装或宣称真机性能通过。
