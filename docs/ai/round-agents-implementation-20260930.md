# 局内智能体改造记录 · 2026-09-30

本轮按 `round-agents-contract-20260930.md` 实施普通高级 AI 的主运行链。算法仍在设备本地的 C# 中运行，Godot 负责权威状态和合法动作执行。三家是三个独立的局内状态容器，不是三个在线模型或三份算法代码。

## 已接通的正式链路

- 发牌完成后创建每个 AI 座位的实例；正常单人模式为三个。测试及联机控制器可按明确座位列表创建 1–4 个，不硬编码人类必须坐 0。
- 整局血战结束、牌墙耗尽、重新开局、退出到模式选择时结束并释放本局。某家先胡只转为已胡状态，不能继续请求出牌，其他家继续。
- 每局随机唯一身份及运行代次阻止同局号重开后误用旧请求。终止立即关闭实例并删除结果领取入口；已进入底层计算的线程不会被强杀，返回前再次核验有效性，失效结果不能落地，计算退出后释放剩余引用。
- 出牌、碰杠胡过、自家动作、定缺均进入对应座位的实例。实例内有自己的 Facade、路线记忆、动作缓存与推理缓存。向听等纯数学缓存继续共用。
- 定缺仍用既有 K 神严格评分。正式定缺入口现在记录本家结果，权威状态确认后记为已执行；定缺前的暂定路线随新公开定缺重新评估。其他人尚未公开的选择不会提前进入本家视角。
- 每家观察包含完整的过滤后事件历史及最新快照。事件去重、连续性、旧版本与冲突检查已生效；其他人的真实摸牌、私有可胡碰杠资格、真实听牌标记等输入会被拒绝。
- 已取消“生成动作即登记已执行”的旧路径。提案保持 pending，由权威提交的本家事件/定缺确认改为 executed；状态变化而未执行的提案标记 superseded。杠的各个子类型统一映射为杠执行确认。
- 每家有三份对手观察档案，推断使用本家的公开视角和独立推理缓存。昂贵推断按决策需要更新，记录其依据的视角版本；观察发生变化后，诊断明确标出计划需要刷新，不冒充已经重算。

## 计划怎样参与决策

沿用经过现有实现积累的路线计算及决策比较，迁入本家常驻实例，而非另加一层同义权重：各动作入口都接收同一个本家的持续战略快照。新增可检查计划档案包含主/备用路线、目标花色、牌局阶段、手牌阶段、普通/七对距离、清缺负担、进张及改良、风险取舍、支持/反对当前路线的证据、计划版本与变化原因。

阶段计算统一调用现有剩余摸牌机会/对手压力模型，移除了持续战略模块的另一套旧墙长阈值。定缺公开会复核暂定路线；合法性失效和原有路线优势门槛仍由实际代码执行，而非仅写在解释中。本轮补上清一色目标排除本家缺门、副露跨门后删除清一色路线。

牌墙可用量、听牌程度、路线权重等仍是既有模型估计，不是经过本轮重新校准的实战概率。RiskBudget 明确标作 0–1 启发式风险容忍度。进张明细只在适合计算的合法 13 张保留结构上标为可用；14 张待舍及未清缺场景不把空明细冒充没有进张，实际选择仍由正式候选后继计算。

## 接口落地方式

- `UpdateRoundAgentsJson` 提供 begin / observe / end / restore；observe 使用完整视角快照及连续过滤日志，暂不改为增量消息，以保留可靠重同步来源。
- `AnalyzeAgentDingQueJson` 使用带本局身份、座位和版本的真实状态，不再走无身份的计数入口。
- 原出牌、反应、自家动作接口保留，增加 RoundId / HostGeneration / ViewVersion；Facet 内路由到正确实例。权威层继续用合法性与完整状态签名检查动作，签名已加入唯一局身份。
- `InspectRoundAgentJson` 输出个人计划、对手证据、提案和已确认历史；输出为副本，不能反向修改个人记忆。
- `CaptureRoundAgentJson` 与 restore 支持同一局的版本化检查点；规则、算法、视角不一致则拒绝恢复。恢复前的提案不复用。检查点文本保持 C# 原始 JSON，避免 Godot 将整数重编码成浮点导致恢复失败。
- 保存/恢复要求权威牌局先提供相同的合法视角。本轮没有新增游戏存档按钮，也没有替代真实牌局的存档逻辑。正常暂停保留当前实例。
- 新入口使用源生成 JSON 解码/编码；这属于 NativeAOT 兼容实现，不能代替真机导出与运行验证。

与设计中的逻辑方法对应：ApplyObservationBatch/Resync 由完整观察快照承载；ConfirmActionResult 主要由已提交事实确认，而非为同一事实再传一次修改牌数的 RPC。反应优先级、一炮多响裁决仍归现有权威牌局，智能体不自行合并或执行胡牌。独立 matchId 未额外加入运行状态：随机唯一 roundId 已直接承担本轮隔离，RoundIndex 仅保留局数语义。

## 本轮聚焦验证

证据目录：`research/round_agents_20260930/`。这些是针对本轮变更选择的验证，不是新增默认固定回归清单。

- `core-checks.json`：33 项 C# 检查，涵盖三实例创建、独立记忆、重复初始化/观察、定缺确认、计划更新、隐私输入拒绝、事件缺口、过期版本、并发计算结束失效、新局清空、同局检查点恢复、版本不兼容拒绝、诊断副本隔离及清一色合法性。
- `runtime-checks.json`：20 项真实 Godot/C# 入口检查，涵盖三家原生实例、各自定缺及计划、重复同步、检查点跨语言往返及恢复后同步、重开、旧身份拒绝与退出清理。
- `full-rounds.json`：最终实现连续两局正式流程运行，血战终局与牌墙耗尽终局各一局，无强制中止。此样本只证明流程可完成，不用于胜率或收益提升结论。
- Godot Debug 与 CLI Release 编译通过。具体结果及代码指纹见本证据目录 verification.json。
