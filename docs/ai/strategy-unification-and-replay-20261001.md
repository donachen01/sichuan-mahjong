# 战略统一与逐步复盘：2026-10-01

目标：每家独立维护计划，以自己的手牌和公开信息决策；正式行动与模拟复用同一套行牌代码；记录当时的证据、选择、执行与后续结果，支持离线重放。

## 已接入的链路

1. `SichuanStrategyContract` 统一发展目标和贪自摸退出条件。每家计划、当前接胡判断、模拟接胡判断读取相同条件；准许拒胡并不等于应当拒胡，正式入口仍需完整终局收益比较及独立样本确认。
2. 后续模拟调用正式的 `SichuanDecisionEngine`、`SichuanReactionDecisionEngine` 和 `SichuanSelfActionDecisionEngine`。删除原来单独按结构距离选牌的模拟出牌算法，也不再用“碰后距离下降”和“有补杠就补”代替实际动作判断。
3. 每个模拟世界为四个座位分别维护路线大脑。根座位继承自己的当前计划；其他座位依据各自模拟手牌与公开信息建立计划，不读取根座位的记忆。每个座位只能知道自己的摸牌与过牌记录，不能看到其他模拟手牌或后续牌墙。
4. 碰杠反事实中已计入的路线成本不在最终排名时重复扣取。此前拆过刻子不再单独罚 1200 分。路线承诺只用于维持/切换计划，不再次修改原始路线权重。七对机会成本仍需估计，没有假装已经完成概率校准。
5. 多杠局面优先使用结构化碰杠组数；只有一种合法缺门弃牌时直接选择该牌，两处优化与正式/模拟入口共用。

## 模拟精度边界

共用策略不等于无限深搜索。模拟内明确关闭嵌套整局搜索和额外二层前瞻；后续拒胡收益仍采用有限期近似，当前真实接胡决策保留完整配对收益确认。报告中标记 `production_policy_bounded_search_v1`。

因此，规则条件、动作代码与路线维护已共用，但不同搜索深度仍可能导致选择差异。不能声称每个节点都等价于无限预算实战，更不能将当前启发式值解释为校准过的真实期望收入。

独立模拟世界限最多四个工作线程，结果按样本顺序汇总，不共享座位计划。清一色可达性使用包含手牌、余张、副露、花色和组数的精确缓存；不通过读取隐藏牌或降低样本门槛加速。

## 决策与执行记录

每个座位的 `AgentDecisionTrace` 保存：

- 局/代次/座位/观察版本/决策编号，输入指纹与策略版本。
- 当时的主路线、备用路线、计划依据、自家手牌与公开积分。
- 候选动作、选择分、评分单位、可用的模型估值与准入证据；没有估值时保留空值。
- 最终选择、待执行/已执行/已被替换/恢复失效等状态。
- 执行确认事件，以及执行时实际积分变化。
- 随后的公开积分、自家是否胡牌、重新评估后的路线和结构距离。

同一观察重试不重复计数。权威事件确认后才记为执行，发出建议不算执行。恢复保留历史，但恢复前未执行的建议失效。返回快照深复制，不能通过修改检查结果污染记忆。

后续积分变化只表示轨迹关联，不把一次自摸或放炮当作某一步决策的因果贡献。当前不会因一局输赢自动修改权重。

## 本地保存和离线复盘

真实 C# 运行入口默认写入 `user://ai_replays/decisions-*.jsonl`。在 Mac 上位于游戏用户数据目录。文件包含原始请求、原始返回，以及计划/执行快照。观察更新会记录，结束前保存各座位完整决策历史，因此智能体消亡后记录仍在。

这是本地文件，没有上传。保存失败通过运行时警告和 `GetDecisionAuditError` 暴露；不能悄悄用替代动作掩盖错误。

- `tests/current/SichuanDecisionReplayRunner.gd`：在新的 C# runtime 中按顺序重放，关闭重复记录，比较最终动作，兼容完整 JSON 和 compact 返回。策略版本不匹配时拒绝假称同版复现。
- `tools/ai/review_decision_journal.py`：生成中文 Markdown 报告，列出每步计划、理由、候选、执行与后续观察，不修改算法。
- `GetDecisionAuditPath`：查询当前日志位置。

当前日志版本只记录策略合同版本；复现应保留对应工程源码及构建。它不是自动归档源码的模型仓库，也不是全策略强度评估系统。

## 本次验证范围

只选择与修改直接相关的检查：真实出牌记录、权威执行确认、重试去重、恢复失效、快照隔离；原有发展与贪自摸收益场景；真实 Godot C# 的定缺/胡牌/强制缺门弃牌入口；日志保存、结束归档与离线重放。详细结果保存在 `evidence/strategy_unification_20261001`。

本轮不打包、不安装设备、不宣称真机性能或总体胜率提升。复杂多样本场景耗时明显增加；后续优化应优先做精确缓存与重复计算消除，并保留本轮复盘证据，不重新引入另一套模拟打法。
