# 统一策略后的性能诊断与第一轮精确优化

本轮目标是减少相同计算和独立样本之间的串行等待，保持真实决策与后续模拟的策略一致。没有减少确认样本、放宽统计门槛，也没有引入超时自动出牌。

## 已实现

- 普通型上听数改用按花色分解的精确组合计算；保留旧枚举器作对照。
- 胡牌布尔判断复用精确距离；需要番型时仍进行完整牌型分析。
- 线程内复用不可变花色分解结果；改良进张结果使用有容量上限的缓存，键包含手牌、余张、副露和缺门。
- 一次出牌内复用已完成的候选牌形、上听数和有效进张分析。
- 后续出牌验证的独立样本最多四路并行，候选使用相同的样本和牌墙；按原样本次序汇总，避免调度次序影响浮点汇总。
- 木桶和尾盘后续验证加入搜索计数与模块耗时；即使最终没有改选动作，也记录已经执行的模拟。样本计数是各批样本数之和，并非候选分支数或模拟内出牌次数。
- 增加显式开启的诊断计时器，正常玩法默认关闭。诊断计时含嵌套调用，不能把各模块时间直接相加。

## 定向验证

证据位于 `evidence/strategy_performance_20261001/`。

- 12,000 个合法手牌距离与旧枚举器逐项一致；2,000 个胡牌判断及指定成牌样例与完整牌型枚举一致：`exact-final.log`。
- 单条固定完整模拟保持净分 1，模拟作用域正确恢复：`final-probe.log`。
- 放胡收入成本测试通过，32 样本比较与生产入口完成：`income-cost.log`。
- 改听、单行道、后续合理放胡测试通过：`development.log`。
- 决策执行、确认、重试、隔离、恢复的记录测试通过：`journal-final.log`。
- 桌面真实 C# 入口、记录和回放：`runtime.log`，45 项检查、19 次调用。此次没有进行 iOS 构建或真机验收。

## 实测边界

以下是 Mac 上的诊断样例，不是手机时延，不是 P95，也不是大量真实牌局平均数。

| 场景 | 本轮结果 | 解读 |
| --- | ---: | --- |
| 基础出牌，关闭根节点完整后续验证 | 首次约 245 ms，重复相同状态约 25–27 ms | 只能说明基础计算与缓存效果，不能当成完整出牌时延 |
| 一条完整后续轨迹 | 约 1.38 s | 相同 Release 探针此前约 1.9–2.1 s，净分不变 |
| 32 样本胡/过比较 | 约 13.1 s | 独立测试记录 |
| 完整生产胡/过选择 | 约 48.8 s | 仍不适合直接阻塞界面 |
| 普通出牌触发完整木桶验证 | 约 65.6 s | 修复前报告错误地显示未搜索；见后续带计时复测 |

历史 146 秒使用 Debug，本轮 48.8 秒使用 Release，不能将两者之差全部归因于算法优化。部分诊断运行有其他构建任务并发，数字只用于定位量级。

带计时复测 `full-discard-instrumented.log`：总耗时 68.17 秒，其中木桶后续验证 67.94 秒；报告正确显示搜索已使用、128 个批次累计样本，出牌仍为牌型编号 16。这确认当前瓶颈几乎全部在完整后续验证。最后追加的统一候选排名计时字段已编译通过，未为单纯增加计时再次运行分钟级样例。

## 尚未解决

整段后续模拟仍反复执行每家每步的完整策略评估。单轨迹已包含数十次出牌、百余次读牌分析；乘上候选分支、发现样本和独立确认样本，形成主要成本。基础上听数提速不能单独消除这项开销。

后续需要在保持策略一致的前提下，进一步拆分可增量维护的读牌、计划和牌形计算，验证不同状态间安全复用的边界。当前移动端同步入口仍可能阻塞界面；内部样本并行不等于界面异步，不能宣称卡顿已经解决。

## 2026-10-02 接续验证与胡牌拆分优化

- 恢复上一会话证据：公开历史预计算通过 12,800 次逐位一致性比较；牌形缓存通过 1,000 个冷/热对照。对应 `likelihood-equivalence.log`。
- 在完整胡牌拆分前使用精确胡牌布尔判断，排除不能成胡的手牌；可以成胡时仍完整拆分，保留全部番型分析输入。原拆分器作为独立对照保留，不使用简化评分或减少样本。
- `decomposition-filter-equivalence.log`：12,000 个距离、2,000 个胡牌判断，以及 2,000 个构造成胡手牌和各自听口与原枚举器一致；覆盖 0–4 个副露、七对开关、可见余张和拆分内容。
- `decomposition-filter-development.log`、`decomposition-filter-single-lane.log`：改听、后续放胡和单行道聚焦验证通过。
- `decomposition-filter-income-cost.log`：真实胡／过生产入口、收益拆分、动态退出、同番锁胡、杠分与呼叫转移等已有聚焦场景通过；32 样本胡／过比较净分及标准误与此前记录保持一致。
- 单轨迹为 1.17 秒，净分仍为 1，作用域恢复正确：`decomposition-filter-probe.log`。
- 完整相同出牌样例为 54.81 秒，木桶后续验证 54.59 秒，仍出牌 16、累计 128 样本：`decomposition-filter-full-discard.log`。上一轮历史预计算后的相同样例为 65.76 秒，单次观测下降约 16.7%；这不是配对多次性能统计，不能推广为所有牌局或手机收益。

调用链核查：`GameState._start_ai_turn_background_request` 调用 `AIManager.start_turn_analysis_background` 时采用默认参数，后者优先执行 `_start_native_turn_analysis_sync_delivery`，然后才考虑原生后台接口。反应入口有同样的同步优先安排。因此“已有后台接口”不能证明实际玩法不会冻结。此次未修改同步决策约束，也未进行真机验证。

卡顿仍未解决。木桶发现阶段会比较风险边界内的全部同距离候选，每个候选都进行完整终局轨迹，随后另做 96 个独立确认样本；这个计算规模仍是根本开销。精确过滤能改善成本，但现有证据不支持把本轮称为体验修复完成。

后续用户明确了实战与研究的边界，已将这些终局比较移出实战入口。2026-10-02 的最终实现和新证据见 [实战策略与研究终局模拟的边界调整](strategy-live-research-boundary-20261002.md)。上述秒级数字仍是此前实现的历史测量，不是调整后实战的现状。
