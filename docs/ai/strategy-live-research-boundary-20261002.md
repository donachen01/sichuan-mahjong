# 实战策略与研究终局模拟的边界调整

## 目标与原因

用户确认：实战动作依据当前合法信息、全局计划及已建立的策略作出，执行后记录事实并复盘；完整终局模拟用于测试与研究，不应成为每一手决策的必经步骤。

此前把“完整依据”实现成多个候选的终局轨迹比较，导致固定桌面出牌样例需要 54.81 秒。历史性能记录继续保留，不能将此前优化过程解释为当时已经解决了卡顿。

## 最终实现

- 实战出牌移除木桶终局确认、尾盘终局确认及统一候选排名中的终局净分覆盖。保留木桶当前结构指标、牌形与番型精确分析、读牌推断、进攻防守、路线和已有短层前瞻。
- 实战胡／过使用同一发展策略：当前听口、公开供应、付款家数、危险、拒胡额度、已兑现杠和当前收益作判断。既有自摸折减及危险门槛不变，并将局部策略值明确标为代理估计，不能称作模拟终局净收益。
- 历史缺少本次弃牌上下文时，不仅凭额度或代理值拒绝合法胡牌；抢杠胡、杠上炮及其他收手条件继续兑现胡牌。即使传输标记是普通 `discard`，也从公开动作顺序识别杠后弃牌，不丢失杠上炮规则收益。
- 拒胡后可以按相同局部碰杠策略选择具体动作，保留碰后计划弃牌、牌形和理由，避免将真实执行元数据压成单一“过”。
- 完整模拟保留在明确研究入口 `AnalyzePublicContinuation`、`AnalyzePublicHuContinuation`、`AnalyzeDiscardHuWithPass` 及研究选择器中。每个终局模拟入口检查决策作用域，若在实战动作计算中调用则报错，不用回退动作隐藏越界。
- 研究轨迹现在调用常规实战策略，不再自动改用轻量动作策略或关闭二层牌形前瞻。短层分析可以随状态重估，但不能再启动嵌套终局模拟。
- 策略版本为 `strategy-contract-v2-live-local`，智能体版本为 `round-agents-v2-live-local`。旧算法版本的检查点不能按新算法直接恢复，避免把旧策略提案当作新策略结果。
- 原有动作理由、候选记录、执行确认、失效、重试、独立座位记忆和回放继续保留；查询本身不会消耗拒胡额度。

## 本次观测

证据目录：`evidence/live_strategy_boundary_20261002/`。下面是本次已运行的聚焦验证事实，不是后续默认回归清单。

- 相同完整出牌样例，Release 首次 **238.70 ms**，仍出牌 16，终局模拟为零。木桶当前结构计算约 4.25 ms。此前同一状态完整终局确认耗时 54.81 秒。见 `full-discard.log`。
- 真实 Godot/C# 桌面入口首次 **373 ms**，重复相同状态 **2 ms**，均合法出牌 16。重复结果含缓存，不能视作下一手耗时。见 `discard-runtime.log`。
- 55／12／4 张牌墙的实战出牌和胡／过局部策略、实战／研究动作一致性、研究入口越界拒绝通过：`live-strategy-boundary.log`。这些样例并非完整真实牌局平均数或手机 P95。
- 定缺分布下的拒胡额度、收手条件、危险与兑现杠，以及代表性策略通过：`distinct-dingque-hu.log`、`representative-hu.log`。
- 木桶当前结构和局部牌形知识仍通过对应测试：`bucket-3-5.log`。
- 发展、改听及 32 样本完整研究轨迹通过：`development-policy.log`。研究轨迹仍可继续战略拒胡。
- 完整研究胡／过比较、物理副本、动态退出、顺胡锁、杠与呼叫转移等已有场景通过：`hu-income-cost.log`。生产胡／过选择约 1 ms，不再启动该研究比较。
- 统一研究与实战动作后，研究胡路线均值从此前的约 1.202 变为约 1.240；过路线约 2.871。数值不是永恒正确答案，变更原因是研究轨迹现在也使用常规局部策略。不能声称本轮所有研究结果逐位不变。
- 动作依据、执行确认、重试、隔离与恢复通过：`strategy-journal.log`。
- 真实 Godot/C# 复盘与回放为 45 项检查、零失败、19 条真实调用回放：`journal-runtime.log`、`runtime.json`。发展与代表性策略的普通 JSON 和紧凑返回一致，见对应 `*-runtime.log`。
- Release 核心构建和桌面 Godot/.NET 构建均通过，零警告、零错误。

## 验证边界

这次完成的是实战决策与研究模拟的调用边界纠正，并消除了已知固定样例的分钟级终局计算。没有测完整交互牌局的帧率与长期时延分布，也没有重新导出 iOS、检查 AOT framework、安装或验证 iPhone。桌面紧凑返回测试不等于 iOS AOT 验证。

局部策略的机会和风险估计仍需要研究验证；一次输赢不能直接判定当时决策是否正确。研究结果也不会在实战中自动修改权重。

一次既有复盘 runner 的默认输出路径覆盖了历史 JSON。本轮证据已单独保存，历史快照根据未改动的历史调用记录恢复；原始历史日志未改动，但 JSON 无法保证逐字恢复。具体来源见本轮证据目录的 `evidence-recovery.md`。
