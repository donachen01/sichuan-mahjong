# 三家高级局内智能体设计约定

日期：2026-09-30。状态：设计已明确；正式主链实施进度及接口映射见 [改造记录](round-agents-implementation-20260930.md)。适用范围：一个人类玩家与三家普通高级 AI 的本地牌局；联机时由权威房主运行同一机制。地狱全信息/协同模式不混入本契约，后续适配须使用独立信息模式与状态容器。

## 1. 总体边界

- 每局创建三个 C# `SichuanSeatAgent`，都具备起手分析、定缺、对手推理、路线规划、动作搜索及策略调整能力。能力相同，私有状态不同；不以随机人格代替正确决策。
- `SichuanRoundAgentHost` 管理本局生命周期和有序调度；不为三家制定共同获利目标，不向一家提供另一家的私有推理或暗牌。
- Godot 权威牌局负责规则、真实状态、视角过滤、事件提交和动作执行。UI 只负责展示。C# 智能体不能自行修改真实牌局。
- 共享向听、进张、番型、规则计算和无观察者信息的纯数学缓存；个人观察、对手分布、路线记忆、决策缓存、搜索随机流归各家所有。旧模块中可变共享缓存须逐一迁移或证明其完整隔离键，不能仅用三个包装对象宣布隔离完成。
- 重用现有算法，避免复制三套代码。核心置于 AI.Core，不依赖 Godot 节点或场景树；本机 C# 运行，不接在线模型。

## 2. 生命周期

### 2.1 身份

- `matchId`：一次对局会话的唯一标识。
- `roundId`：每次新发牌生成的唯一标识，重开同一局号也必须改变；保存并恢复同一局时保留。
- `agentId`：由 roundId 与 seat 组成；三个席位显式传入，不假定人类永远在座位 0。
- `hostGeneration`：恢复/重建运行容器时更新的代次，阻止重建前的计算结果落地。
- 现有 `RoundIndex` 仅表示展示与积分语境，不再作为唯一生命周期身份。

### 2.2 状态与转移

| 状态 | 进入条件 | 允许行为 | 离开条件 |
|---|---|---|---|
| Created | 权威发牌事务完成，三份合法初始视角准备好 | 建立起手结构和记忆 | 进入规则指定的开局阶段 |
| Opening | 换三张（如启用）、定缺及其公开过程 | 按顺序处理本家换牌、计算定缺、形成暂定计划 | 定缺完成并进入正常行牌 |
| Playing | 本家仍参与摸打 | 观察、推理、规划及合法动作决策 | 本家胡牌或整局结束 |
| Won | 本家已胡，血战仍继续 | 接受已公开结算等事实，保留本局档案；不再摸打或搜索动作 | 整局结束 |
| Closing | 权威提交整局终止事实 | 冻结最终档案，取消计算、撤销待执行提案 | 清理完成 |
| Disposed | 本局结束或明确放弃本局 | 不再接收观察或动作请求 | 无；新局创建新对象 |

- 三个智能体在同一开局事务中全部成功建立后才开放决策；失败则回滚初始化并报告错误。
- RoundEnded 指完整血战结束并确认最终结算；一人胡牌不是 RoundEnded。
- 退出、重开、切换对局通过 AbortRound 清理本局。暂停/切后台不等于结束；恢复前同步到最新合法视角。
- EndRound/AbortRound 幂等。取消任务后，即使后台计算稍后返回，也不得提交结果或写记忆。所有调用先校验 roundId 与 hostGeneration。
- 生命周期事件是主要依据，移除依靠手牌距离、墙长突然增大等方式猜测新局的正式职责。
- 下一局不继承对手画像、路线承诺、风险预算或个人记牌。外部离线复盘可以保留记录，但不能暗中作为下一局个体记忆输入。公开累计积分仍属于新局的合法初始事实。

### 2.3 同局恢复

持久化每家经过过滤的事实记录、版本化计划检查点及规则/算法版本。恢复同一局时创建新运行对象并恢复该局状态，随后补齐检查点之后的事件；这不是跨局继承。原始事件缺失时只允许以权威快照重建可恢复信息，将历史推断标为未知，不能伪造舍牌顺序。算法版本不兼容时由可用事实重建计划并明确记录；不能无提示声称精确延续旧计划。

## 3. 信息边界

| 数据 | 本家智能体可读取 | 处理规则 |
|---|---|---|
| 本家起手、摸牌、暗手 | 是，精确值 | 只进入本家视角和个人缓存 |
| 四家公开弃牌、副露、庄家、积分、已胡状态 | 是 | 以本游戏实际公开规则为准；暗杠展示未公开的细节不能擅自传出 |
| 定缺 | 已公开部分及本家已确认选择 | 同时选择阶段不泄露其他家的未公开选择 |
| 他家摸牌 | 发生、座位、公开张数变化 | 具体牌种隐藏；未知不能当作某种牌 |
| 他家手切/摸切 | 仅当游戏确实公开此信息 | 来源未公开或无法确定时标 Unknown |
| 他家真实暗手、真实听口、牌墙构成和顺序 | 否 | 不进入普通 AI 请求、缓存或搜索种子 |
| 他家本可胡碰杠但选择过 | 否，除规则明确公开 | 不通过私有资格标志或完整 pass 矩阵泄露 |
| 本家过胡限制和合法动作 | 是 | 规则层提供事实，智能体不能自行解除限制 |
| 他家需求、听牌可能性、花色集中倾向 | 只能推断 | 保存依据、反证及置信边界；与确定事实分开 |

- 其他两家电脑也是对手，三家不得交换暗牌、个人计划、推理分布或搜索结果。
- 公开日志可共享只读存储；各家独立解释日志，并拥有各自的三个对手档案。
- 保留现有字段语义：`Visible18` 为公开可见牌；`Remaining18 = max(0, 4 - Visible18 - Hand18)`。Remaining18 已扣本家手牌，后续不得再次扣除。未见副本不等于牌墙副本。
- 输入 27 种牌计数；本轮迁移不顺便重命名历史 Hand18 等字段。增加 schemaVersion 明确编码约定。
- 观察对象进入智能体时冻结或拷贝，不能共享可变数组。全信息诊断路径不得复用普通模式个人容器。

## 4. 事件与接口

### 4.1 交互方法（逻辑契约，具体传输方法名在实施时映射）

| 方法 | 输入重点 | 返回/副作用 |
|---|---|---|
| BeginRound | 身份、规则与策略版本、三家座位、各自初始视角 | 三家就绪状态和各自观察版本；同身份同内容重试不重复创建，内容冲突拒绝 |
| ApplyObservationBatch | 指定观察者、连续事件批次、批次后的视角版本及摘要 | 处理到的游标；不直接执行动作 |
| Decide | 本家身份、requestId、决策类型、当前观察版本、完整合法动作参数 | DecisionProposal；可以是定缺、出牌、反应或自家动作 |
| ConfirmActionResult | proposalId、已执行/被抢先/过期/拒绝、权威事务版本 | 关闭待确认提案；牌数变化仍由对应观察事务更新一次 |
| Resync | 本家合法完整快照、可用历史与检查点、版本 | 恢复一致性；不把快照重复当成新事件累计 |
| EndRound / AbortRound | 本局身份、最终事务版本、结束原因 | 取消任务、封存可选诊断、释放三家及所有局内引用 |

初始化请求虽可批量承载三份视角，Host 只能分发；SeatAgent 构造及算法调用只接受本家视角。不能把整个批量对象传入算法。

### 4.2 版本与顺序

- 外层信封：schemaVersion、matchId、roundId、hostGeneration、observerSeat、rulesVersion、policyVersion。
- 每家使用独立递增的 `observationSeq`，表示实际发送给该家的过滤后事件序列。不能要求各家序号完全相同，私有事件可导致差异。
- 每个观察事件包含 eventId、observationSeq、transactionId、事件类型、行动座位、合法可见内容及信息范围。事件编号不得编码暗牌内容。
- `viewVersion` 表示一次权威事务后本家可见状态版本，`planRevision` 表示本家计划版本；两者职责不同。原 EventVersion 可保留适配，但不能混用为三种版本。
- 按序幂等处理：重复 eventId 且内容一致则确认但不重复应用；同序号内容冲突或发现缺口则返回 NeedsResync。补齐前不基于过期记忆产生可执行提案。
- 批次原子提交：一炮多响、杠的确认及补牌时序等按规则事务表达。涉及同时结算的多家胡牌必须合并提交，不能让智能体依据半完成的结算状态行动。

### 4.3 必须表达的事实事件

RoundStarted；本家 ExchangeCompleted（如适用）；本家 DingQueCommitted；DingQueRevealed；DrawObserved；DiscardCommitted；MeldCommitted（碰/明杠/暗杠/补杠按规则区分）；ReactionResolved；WinsCommitted；ScoresSettled；RoundEnded。

- DrawObserved 对他家隐藏牌种；本家可包含确切摸牌。
- 抢杠等流程先表达规则已确认的状态，不能把尚可被抢的补杠当作已完成副露。被碰走的弃牌通过事件引用从当前牌河移除，历史事件仍保留，但不可重复计数。
- 本家过牌锁等用私有规则状态更新，不为其他观察者提供私有反应资格。
- 原 `SichuanPublicEvent` 作为旧算法需要的公开事件投影保留；新生命周期和私有事实用外层观察契约表达，不能直接把私有消息塞进 PublicEvents。

### 4.4 提案与执行

DecisionProposal 包含 proposalId、requestId、本局/本家身份、basedOnViewVersion、planRevision、decisionWindowId、动作及参数、精简 reasonCodes。开发诊断可另取候选比较与计划详情，移动端正常返回不必携带长文本。

- 相同请求与相同状态重试返回一致提案，不增加路线承诺或重复记忆。
- 同一反应窗口允许多家同时给出提案；决策窗口由权威规则层保持，收集提案期间不把“正在考虑”当作牌局已变化。最终统一裁决一炮多响及动作优先级。
- 权威层执行前检查本局、代次、窗口、状态版本与合法性。窗口已结束或状态变化则拒绝旧提案并按需要重新请求。
- 提案不是事实：碰被胡牌抢先、请求取消、动作未执行，均不能写成已碰/已舍。
- 思考可以更新当前事实下的计划；“已执行动作”历史只在确认后登记。搜索分支使用独立副本，不能调用真实 Agent 的记忆提交方法。

## 5. 计划结构及更新规则

### 5.1 每家持有的结构

| 结构 | 必须保存的内容 |
|---|---|
| ObservationState | 最新合法视角、处理游标、确定牌数、带来源的公开行为历史 |
| OpponentModels[3] | 缺门/清缺事实、手切摸切时序、副露、退出状态；需求、范围、威胁等推断的支持证据、反证及最后更新时间 |
| OpeningAssessment | 起手结构、三门 K 分、实际定缺及理由、保留两门的速度/做大条件；换三张后重新评估 |
| HandAssessment | 普通型、清一色与七对距离、清缺负担、有效进张、同向听改良、公开副本与墙内估计分开；清色另报合法目标与距成牌所需张数 |
| RoundPlan | 主路线、备用路线、目标花色、当前阶段目标、候选路线依据、转换条件、风险取舍及计划版本 |
| ExecutionState | 待确认提案、已确认动作及当时依据、执行后需要复核的条件 |

OpponentModels 中每个推断应能指回具体事件或模型版本。不要把人工权重转换成小数后称为已校准概率。

### 5.2 RoundPlan 的最小字段

- `primaryRoute` / `fallbackRoute` / `targetSuit`：方向，不是预定动作脚本。
- `objective`：争取本家规则收益；结合公开积分局势确定取舍，不能汇总三家电脑收益。
- `tablePhase`：按本家剩余摸牌机会、未胡人数、规则终局压力评估。
- `handPhase`：未清缺/结构未齐/结构成形/一向听/听牌，同时保留普通型与七对不同距离。
- `pressureState`：各对手威胁和证据，不仅保存一个最大值。
- `nextMilestone`：当前阶段希望改善的结构，例如清完缺门、补足结构、扩大成叫进张或维持合法听牌。
- `supportingEvidence` / `counterEvidence`：当前路线为什么值得继续，哪些事实不支持它。
- `continueConditions` / `switchTriggers` / `abandonConditions`：可由当前状态计算的条件；不是自然语言口号。
- `riskBudget`：有明确单位与估价来源的本轮风险取舍；模型尚未校准时标明估计性质，不伪装成精确损失保证。
- `routeAssessments`：候选路线的合法性、结构距离、供给、潜在收益、机会成本和不确定性。不可比较的启发式分数不能直接称为同单位净收益。
- `planRevision` / `basedOnViewVersion` / `changeReason`：什么证据导致何种变化。

### 5.3 怎样真正参与行动

1. 先核验当前信息与合法动作。清缺、过胡限制等规则不能被计划覆盖。
2. 用共享算法计算候选动作真实后继，含碰后首打、杠后补牌与血战时序。
3. 比较自身推进、进张和改良、路线保留/破坏、对手风险与四川规则收益。
4. 计划为候选比较提供目标和条件，不再作为多个模块反复叠加的同义奖金。整理现有修正项，明确每个因素只在哪一层计价。
5. 判断是否满足换路条件，再输出当前动作提案。真正执行后用新事实复核。

定缺继续严格执行已确认的 K 神评分法（三连坎 +3）。计划可记录其后果、按已约定同分规则处理，但不得暗中覆盖唯一最低分选择。其他人的定缺公开后，再形成包含花色竞争的初始整局计划。

路线稳定依据应是持续有效的收益和证据，而不是调用次数。相同事件不重复提高承诺；明确不合法或关键前提已失效的路线立即退出。接近的路线可保留稳定区间以减少摇摆，具体阈值需独立验证，不在本设计中随意定权重。

对手一次切牌通常只更新档案；定缺公开、清缺、碰杠胡、关键副本耗尽、自身距离改变、残局付款人数改变等会标记相关计划为待复核。不存在一张牌必然证明对手持有什么的硬读心规则。

## 6. 运行效率与恢复顺序

- 观察更新轻量，较重的推理/搜索按行动需求运行；重大变化先标记相关模块失效，在决策前完成所需重算。三家不会每个事件都各跑完整搜索。
- 每家单写者维护记忆，决策在固定版本快照上计算。先采用有序后台调度，避免堵塞 UI；是否并行由设备测量决定，独立智能体不要求三个常驻工作线程。
- 同一观察版本复用个人推理结果；纯结构缓存共享。缓存键包含规则/策略版本及全部相关输入，个人缓存另带观察者与本局身份。
- 搜索随机流不依赖其他 AI 的调用次序；固定同一合法视角与种子应可复现。花色置换仍需检查算法自身对称性，不能认为独立对象自动修好历史不一致。
- 先保留现有 JSON 与完整快照的可靠通路，C# 常驻个人记忆；接口支持事件批次、去重和补齐后再减少重复快照。不设“超时就让前端随便出牌”的替代策略。
- iOS 使用现有本地 NativeAOT 路线；新增消息采用 AOT 安全解析/序列化方式。性能、内存与三台真机表现属于实施后的验证，本文不声称已经测量。

## 7. 现有工程迁移位置与完成定义

| 现有位置 | 迁移职责 |
|---|---|
| autoload/GameState.gd 与权威牌局流程 | 明确 Begin/End/Abort、唯一局标识、事件事务和动作确认 |
| scripts/ai/csharp_ai_bridge.gd | 每家合法视角、契约信封、定缺关联身份、过滤后事件序列 |
| scripts/ai/AIManager.gd | 生命周期转发、请求/窗口管理、过期结果拒绝；不承载策略 |
| scripts/ai/SichuanCSharpRuntime.cs | AOT 安全消息入口与 Host 适配；不额外复制一份记忆 |
| dotnet/AI.Core/Entry/SichuanAiFacade.cs | 接入 Host/SeatAgent，出牌、反应、自家动作、定缺使用同一个本家上下文 |
| SichuanRoundBrainEngine / SichuanRoundStrategyBrain | 将已有路线记忆迁入 Agent，统一阶段依据，保留可验证能力，避免两套战略互相覆盖 |
| SichuanStateView / SichuanPublicEvent | 保留算法视图及公开事件投影，外层增加生命周期/私有观察契约 |

实施先完成生命周期与隔离，再贯通事实更新/确认，再接入计划与策略条件，最后做性能优化。没有通路证据时不能用类名、日志或接口存在声称功能完成。

本设计完成标准：三家从开局到整局结束各有且仅有一个有效实例；新局无个人记忆残留；每家输入合法且观察顺序完整；待确认与已执行动作分开；所有决策入口使用同一家计划；计划变化有事实依据；任何失效提案均不能执行。实施时只选择与当次改动直接相关的聚焦验证，不新增或默认执行固定回归清单。

本文件不代表既有算法缺陷已修复，不代表三家已迁移，不代表实战棋力或真机性能已通过验证。
