# 3-20 D与刻子旁单张的共享决策修复（2026-10-11）

本次关闭上一轮复核发现的3-20 D缺口，并修复相关的不足五组理牌问题。当前桌面游戏在教材3-20 D的明确补全条件下，普通、轻量和精简入口均打4筒且实际落入牌河。此前22个条件局面的结果保留。没有使用“四川麻将视频深度学习”技能；没有把本轮验证加入默认回归或CI。

## 原因与实现

3-20 D：筒33345579、条246779，6筒公开3张。修复前五组规划器自身就选9条，最终裁决没有收到另一个建议，故不是前端落错牌或安全模块压过4筒。

当选择9条时，原候补模块把4筒与333筒及未来摸牌合并枚举，给最弱搭的候补供应计为11；选择4筒时为7。这4个额外未见副本来自摸3筒或4筒，原先的高优先级比较因此止步，没有再比较其他搭子的均衡性。计数是局部结构指标，不是胡牌概率；对应续手并非一概非法，问题在于把刻子旁普通单张的发展与顺子可提供的重组能力同等提升到候补比较层。

修复将已成刻子排除出顺子候补重组资源；普通单张仍在原候选评价和保留单张供应比较中发挥作用。这样D两个候选的最弱搭指标相同后，能够继续比较其余搭子，最终选择4筒。3-20 C中的456筒与候补5筒仍能重组，继续打8筒。没有添加牌例编号、花色或固定出牌答案分支，也没有调整供碰权重来追逐答案。

相关扩展验证发现3-19 B原牌面虽然正确，变换后12/24项却错误：原规划器要求当前分组至少五组，排除了“两副已成刻子、现有四组、等待孤张补组”的合法结构，转而拆一副刻子凑搭。不同花色/方向的枚举顺序会选择不同拆法。修复移除“当前必须已有五组”的硬门槛，仍要求将牌存在、牌数合法、实际普通上听数与分解公式一致；保留自然刻子的既有优先级。修复后原形和镜像均保留两副完整刻子，3-19 B的24项变换全部正确。

生产逻辑修改位于dotnet/AI.Core/Engines/SichuanFiveBlockPlanner.cs。现有BucketTheorySmoke中的3-20 D补上最终动作必须为4筒的断言，原结构证据断言同时保留；不再仅凭发现改良机会就把该例视作最终出牌已通过。
