# Android 横屏重力旋转确认与修正（2.6.87 / build348）

## 请求与发现

2026-10-18，用户要求确认安卓是否也正常。连接设备为 Android arm64 模拟设备 yyb_mac / NP05J（ADB emulator-5554），没有连接 Android 真机。本次选择与方向改动直接相关的一次性运行验证，不建立固定回归清单。

build347 实际安装启动后进入单机牌桌，注入左右横屏及竖拿加速度。发现系统自动旋转关闭时不能左右翻转；开启时可以，竖拿始终横屏。保留 [原始失败结果](build347-failure.json)。

Godot 的 SensorLandscape 导出为 Android USER_LANDSCAPE=11，会受系统旋转锁影响。新增 Android 专用自动加载脚本，通过 AndroidRuntime 在 UI 线程调用 Activity.setRequestedOrientation(SENSOR_LANDSCAPE=6)；启动和前台恢复时应用，不改变用户系统设置，非 Android 平台立即返回。未修改 AI/规则算法，iOS 已验收安装包不变。Android 构建号升为 348，应用版本仍为 2.6.87。

依据：[Android screenOrientation 官方说明](https://developer.android.com/guide/topics/manifest/activity-element#screen)、[Godot AndroidRuntime 官方用法](https://docs.godotengine.org/en/4.6/tutorials/platform/android/javaclasswrapper_and_androidruntimeplugin.html)。

## 实际验证

- build348 的 APK 已重新生成、安装启动，v2/v3 签名验证通过，清单 versionCode=348、versionName=2.6.87。
- 实际 Android 日志和窗口服务确认 requestedOrientation=6。
- 系统自动旋转开/关各测试左横、右横、竖拿、平放，共 8 项，全部通过。左/右分别实际进入 ROTATION_90/270；竖拿和平放保持横屏；分辨率始终 2560×1440，应用 PID 始终相同。
- 后台返回仍为 SENSOR_LANDSCAPE，反向横屏仍有效。翻转后双击真实摸进的八万，牌进入牌河，余牌数从 54 变为 53；截图核对牌桌、手牌和操作坐标正常。
- 本轮应用日志没有 SCRIPT ERROR、Parse Error 或 FATAL EXCEPTION。测试结束已恢复系统自动旋转和 user_rotation 原值（均为 0）及原始加速度信号。
- [结构化结果](verification.json)、[原生方向日志](native-orientation.log)。完整窗口转储、运行日志与原尺寸截图保存在本地 `build/android/rotation-2.6.87-build348/`，不上传大型图片。

已验证安卓模拟设备中的真实 APK、Android 方向机制和旋转后触控；不等同于 Android 真机物理传感器验证。未修改或重新安装已获用户验收的 dona iPhone 包。
