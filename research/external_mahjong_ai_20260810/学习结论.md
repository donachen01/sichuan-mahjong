## 2. 四个项目中真正有用的内容

### 2.1 `ebony72/Mahjong`：最高价值，适合做独立血战基线与评测参考

这是四个项目里唯一同时具备四川血战引擎、完整结算账本、较成熟策略、同牌墙配对擂台和隐藏信息反事实评估的项目。

最值得学习的不是单个启发式权重，而是以下方法：

1. **同牌墙换座配对评测**：每个随机种子运行两次并交换策略座位，抵消座位和牌墙差异；用每个种子的配对净分差及 95% 置信区间判断改动是否真实有效。其技术报告指出小样本试跑容易被大样本推翻，建议至少 500 个种子。
2. **终局净分分解**：把胡、点炮、自摸、被自摸、杠、呼叫转移、退税、查大叫、查花猪等全部重建为可核对账本，并验证分类金额之和严格等于最终得分。这与我们的血战 `ActionValue` 目标高度一致。
3. **公共信息一致的隐藏状态采样**：从决策者当时可见信息出发，重采样其他玩家暗手和牌墙；对所有候选动作使用同一组隐藏状态和牌墙，即 common random numbers，显著降低候选比较噪声。
4. **交叉验证反事实后悔值**：不能用同一组有噪声 rollout 同时挑选赢家和报告收益，否则会产生 winner's curse。该项目的同一数据中，原始后悔值看似 `+1.10`，交叉验证后约为 `-0.05`，说明未经留出验证的“最优候选”很容易是假提升。
5. **血战收益不能用胡牌率代表**：高级策略胡牌率更低，却通过更多自摸取得更高净分。其报告中高级策略对发布基线的配对差为 `+2.742/种子对`，95% CI `[+1.510,+3.974]`；高级策略胡牌率 `0.625` 低于基线 `0.697`，但自摸率 `0.296` 高于 `0.220`。这直接说明我们的主指标必须是净分而非单纯胜率/成叫率。
6. **防守的反直觉代价**：只减少眼前点炮可能把对手的点炮胡转成更贵的自摸，也可能损失自己的进攻和点炮收入。防守策略必须比较完整终局净分，不能把“打更安全”直接当奖励。

可借鉴的策略特征包括：未知牌知识库、各花色分布估计、剩余摸牌次数、活跃付款人数、胡/过胡的自摸转化价值、碰杠后的向听和路线变化。但这些只能作为候选特征，不能绕过本项目自己的规则和结算合同。

### 2.2 `Sichuan-Mahjong-AI-Testbed`：只适合接口和弱基线

优点：

- Java 工程把 `shouldPung`、`shouldKong`、`shouldSkip`、`getTileToPlay` 等动作封装成可替换 AI 接口，适合作为策略插件化的简单参考。
- 当前概率 AI 可以充当一个很弱的对照策略，用来证明新策略至少不比基础牌效算法差。

限制：

- README 明确把 Fight To Death 和 Scoreboard 标为 Coming，不能视为完整四川血战环境。
- 当前 `ProbabilityAI` 主要包装基础手牌算法，没有完整公共信息、对手信念、血战结算或全动作反事实。
- 未发现许可证，只能学习结构，不能复制实现。

### 2.3 `sceneun1ty/mahjong-ai`：适合解释界面，不适合做训练标签

优点：

- 输出格式清楚：给出候选弃牌、向听、听口、剩余张数、安全等级和自然语言原因。
- 照片识牌到出牌建议的产品流程，可用于未来“AI 提示/复盘”界面。
- MIT 声明允许在保留许可的前提下复用，但仍需逐文件审查。

限制：

- 核心只有约 460 行 Python，向听和面子统计采用贪心/启发式扫描，不是完整多分解 DP。
- 安全分主要由是否现过、幺九/中张等固定常数构成，无法代表四川血战的真实点炮、点碰、点杠和大牌损失。
- README 的“最优”表述不能代替大量配对对局和独立反事实验证。

最合理的用途是复用解释层设计，不让它成为生产决策器或老师模型。

### 2.4 `chen3kx` Gist：适合做反例与最低基线

代码按 easy/medium/hard 组织，能快速演示难度差异，但 hard 仍是局部计数启发式；`shouldGang` 在多数情况下最终直接返回 true，`shouldHu` 也几乎总是接受，缺少完整碰/过/杠/胡净分比较。

它的价值是建立一个“明显弱策略”基线和反例集，例如：

- 一律杠为什么会破坏中张刻子、宽听和清一色路线；
- 用对子数量决定碰牌为什么会在 2234、5567、残局危险首打等场景失效；
- 仅靠邻张和现张加减分为什么会拆错复合搭子。

该 Gist 未发现许可证，不能复制代码。

## 3. 两篇论文对我们的启发

### 3.1 A2C + 手牌估值论文

官方摘要能够确认的流程是：

1. 先设计基于手牌估值的基础麻将程序 MJE；
2. 用 MJE 自对弈生成深度学习训练数据；
3. 通过训练集、测试集和消融/对比实验选择预训练模型；
4. 把预训练模型作为 A2C 的 Actor，再让 MJE-RL 与 MJE 对弈继续强化；
5. 相对 MJE，MJE-RL 胜率提升 4.08%，点炮率下降 3.02%。

对我们的直接启发是“规则老师预训练 + 强化学习继续优化”，而不是从随机策略开始。我们的 `bone_ash` 可以作为行为老师和冻结基线，能明显缩短探索期，并避免早期模型学到非法动作或毫无牌理的策略。

但其指标不能直接照搬：该论文对象是大众麻将，不是我们的四川血战；胜率和点炮率也不足以衡量自摸多家付款、杠分、呼叫转移、查叫/花猪及提前退出后的净收益。我们必须把平均终局净分和净分分解设为主指标，胜率/点炮率只做辅助指标。

### 3.2 郜翔 2024 南昌大学硕士论文

公开目录能够确认的核心设计方向：

- 博弈特征编码和风格数据集；
- 博弈评估指标体系与风格分类标准；
- 融合决策网络 M-Net；
- 面向麻将多智能体训练的分层强化学习和任务分解；
- 多智能体匹配训练；
- 后提升集中训练；
- 模型对打测试；
- 附录为四川麻将基本规则。

这些方向与我们高度匹配：

1. **分层动作头**：定缺、弃牌、过/碰/直杠/胡、暗杠/补杠/自摸本来就是不同决策分布，适合共享状态编码器、使用不同合法动作掩码和动作头，而不是强行塞进一个平面分类器。
2. **对手/事件注意力**：可以对三名对手、各自弃牌时间序列、副露和定缺状态分别编码，再由注意力/融合层决定本次动作关注谁。这里建议的是基于公开目录的工程推导，不宣称论文已明确使用某种“多头注意力”结构。
3. **多智能体匹配训练**：候选 AI 不能只和自己的同版本四人自博弈。应建立由 `bone_ash`、历史冻结版本、规则型策略和后续学习策略组成的 league，随机匹配并轮换座位，降低互相迁就和策略坍缩。
4. **集中训练、分散执行**：训练 Critic 可以使用模拟器完整隐藏状态来降低方差，但部署到 `bone_ash` 的 Actor 只能读取自己的手牌和公开信息；否则会把 hell 的透视能力泄漏到老手基线。
5. **风格数据集**：可把“老手风格”作为辅助偏好，不作为最终收益标签。用户或可信老手可对争议的拆对、拆搭、碰/过、杠/不杠状态给出排序和置信度，主裁判仍是同规则、同隐藏样本下的终局净分反事实。

## 4. 推荐的进化路线

推荐采用“精确规则内核 + 离线反事实老师 + 学习型价值/策略 + 多智能体联赛”的混合路线，不建议一步到位端到端替换当前 AI。

### 阶段 A：训练环境与客观裁判

1. 保留当前 C# 为唯一规则、合法动作、状态转移和结算来源。
2. 做无界面的高速模拟入口；每个种子能完全复现牌墙、座位、定缺和动作序列。
3. 建逐项净分账本，验证所有玩家账本和恒等于零、每个玩家分类账本和等于最终分数。
4. 建同牌墙换座配对擂台；主报告为平均净分/座位局、配对差、bootstrap/配对 95% CI。
5. 建独立隐藏状态采样器；同一决策的所有候选动作共用同一批后验手牌和牌墙。
6. 反事实裁判按训练/选择与留出评估分离，报告交叉验证 regret，禁止用生产评分器给自己打标签。

### 阶段 B：先学“看局势”和“估价值”

网络输入应只包含部署时可见信息：

- 自己手牌、摸牌、副露、定缺；
- 三家逐时序弃牌、手切/摸切、副露、定缺、是否已胡、分数；
- 活跃玩家、剩余牌墙、当前巡目、杠/过胡/同轮锁和结算状态；
- 精确牌形引擎输出的多分解、向听、真实有效张、听口、番型和路线特征。

建议共享编码器后设置多个辅助头：

- 对手每张牌的持有/听牌/胡牌概率；
- 本动作后成叫概率、番值分布和终局净分分布；
- 弃牌策略头；
- 反应动作头；
- 自行动作头；
- 状态价值头。

先用离线 rollout 产生监督标签，训练 belief/value/ranker；规则合法性和精确牌形继续由 C# 保证。这样可以优先改善当前最明显的拆对子、拆搭子、碰/过和杠/不杠，而不会引入非法动作。

### 阶段 C：预训练后再做多智能体强化学习

1. 用 `bone_ash` 和独立反事实老师的数据做行为克隆/候选排序预训练。
2. 再用 A2C/PPO/MAPPO 一类 Actor-Critic 方法优化终局净分；算法名称不是关键，合法状态转移和奖励合同才是关键。
3. 每个座位使用自己的个人净分奖励，禁止三家共享“围剿人类”目标。
4. Critic 训练时可见完整模拟状态，Actor 执行时严格屏蔽隐藏信息。
5. 使用冻结历史策略联赛、随机匹配、座位轮换和课程学习；稀有的碰/杠/过胡状态单独分层采样。
6. 新模型先影子运行，只记录它会选什么，不实际接管手机对局；通过盲测后才升级 `bone_ash`。

### 奖励设计

主奖励只使用项目真实终局个人净分，完整包含：

- 胡/点炮/自摸/被自摸；
- 暗杠、直杠、补杠及抢杠；
- 杠上花/杠上炮；
- 呼叫转移、退税；
- 查叫、花猪；
- 活跃付款人数和玩家胡牌退场后的后续收益。

可增加辅助预测损失和 potential-based shaping，例如终局价值预测、对手听牌概率、精确牌形潜力差，但不要直接奖励“碰”“杠”“向听下降”或“保对子”。否则模型会钻奖励漏洞，机械碰牌、机械杠牌或为了成叫拆坏高收益结构。

## 5. 评测指标

主指标：

- 同牌墙换座的平均终局净分差及 95% CI；
- 一席候选 AI 对三席冻结联赛基线的净分，而不是四席都换成同一新 AI；
- 分动作反事实 regret：弃牌、碰/过、直杠、暗杠、补杠、胡/过胡分别统计。

辅助指标：

- 胡牌率、自摸率、自摸净收入、点炮率、点炮损失、被自摸损失；
- 非必要拆对子/拆搭子率；
- 成叫率、首次成叫巡目、真实听口、查叫/花猪净分；
- 碰/过错误率、杠净收益、路线切换率；
- 对手持牌/听牌/胡牌预测的 Brier、ECE；
- 同状态重复决策一致率；
- iOS 决策延迟 P50/P95/P99。

## 6. 结论与建议

四个项目里，`ebony72/Mahjong` 最值得先用于方法复现和独立基线；A2C 论文最值得借鉴“规则老师预训练后再强化”；郜翔论文最值得借鉴“分层动作、融合局势、多智能体匹配和集中训练/分散执行”。其余三个项目只应承担解释层、插件接口、弱基线或反例职责。

建议下一步先做阶段 A，不先训练大模型：把当前 `bone_ash` 与 `ebony72` 高级策略接入同规则适配器，在完全相同的项目规则和结算下跑 1000 个配对种子，确认净分账本、反事实裁判和训练数据管线都可信。只有这一步通过，后续 A2C/MAPPO 才会优化正确目标，而不是更快地学会当前模拟器或奖励函数的漏洞。
