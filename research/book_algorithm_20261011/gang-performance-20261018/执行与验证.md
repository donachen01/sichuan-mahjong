## 同一输入的耗时

使用已保存的真实公开反应输入 `own-gang-real-input.json`，同一完整字段加载器、Debug 核心、各自新进程运行；输入为四家仍在场、墙38、9万反应窗口。当前默认与候选分别测量，不能将两套分值理解为同一策略应一致。计时器仅显式研究时打开，区分包含子调用的总时间与自身时间，表中模块均为自身时间，避免重复相加。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| current 整次决策 | 10.280 秒 | 5.465 秒 |
| 两阶段候选整次决策 | 34.699 秒 | 13.982 秒 |
| 候选：对手流局听牌预测 | 23.822 秒 / 322 次 | 6.011 秒 / 322 次 |
| 候选：清色前瞻自身 | 3.111 秒 / 325 次 | 2.377 秒 / 325 次 |
| 候选：手牌改良 | 3.114 秒 / 5476 次 | 1.269 秒 / 5476 次 |
| 候选：原有固定听口概率计算 | 1.281 秒 / 2747 次请求 | 实际递推 0.407 秒 / 385 次，仍2747次请求 |

两阶段新增递推本身优化前约0.08秒，不是此次34.7秒的主因。候选370次共享弃牌策略调用、325次完整排序保持不变。优化前 `qing` 自身时间已扣掉内部其他已计时模块；不能把它的包含时间再次相加。报告是本机此次单次冷进程观察，不宣称统计显著性、棋力提升或手机速度。

[优化前 current](baseline/current.json)、[优化前 candidate](baseline/candidate.json)、[优化后 current](final-current.json)、[优化后 candidate](final-candidate.json)保留每个计时模块、调用次数、动作、分值与理由。中间阶段的 `after-distance-cache.json`、`after-candidate.json`、`after-pruning.json`保留逐阶段观测，最终结果以 `final-*` 为准。

正式 Godot C# 桥接使用相同输入另开进程复验：current **5.063秒**，候选 **14.523秒**，对应[运行输出](runtime-current.json)、[候选运行输出](runtime-candidate.json)。此处未启用详细计时器。独立Probe、生产核心和Godot加载的核心程序集SHA256完全一致，见summary。

## 代码与适用范围

- `SichuanTerminalReadinessProjection`：使用现有数学向听缓存；两遍比较保留原“最少向听、最多有效张、原牌序”的预测语义，省去注定不能胜出的候选的有效张枚举。
- `SichuanPhysicalTargetDistance`：合法目标使用一元位表示，`popcount(H & T)`等于原先逐张累加`min(H,T)`；所有合法目标仍存在，四张上限不变。合法副露/面子/将组合只预计算一次。
- `SichuanActionTreeEvaluator`：一次决策内按完整不可变请求复用概率数值；报告的耗时仍为本次请求耗时，不沿用缓存首次计时。不同请求不会按状态相似度合并，缓存随根决策结束释放。
- `SichuanPolicyTiming`及相关模块：新增自身耗时、调用次数和细分计时。正常游戏默认关闭，诊断不参与选牌。

本轮没有修改收益系数、定缺、防守、退杠或呼叫转移规则，没有删除自家后继分支或减少样本。默认仍为current；两阶段候选的远向听缺口仍在，不能因本轮提速登记为默认实战接入完成。

## 失败与纠正保留

首轮仅用旧简化State辅助加载器诊断，发现未复制部分传输字段后改用完整字段；原始结果保留 `baseline/*partial-loader.json`，不作为正式性能比较。最终比较和Godot复验均针对相同完整输入，不能把历史不同节点秒数拼成速度比。

首次Godot回放测试脚本将JSON数值读为浮点再传回，C#在`currentSeat`整数解析处拒绝。保留[失败输出](runtime-current-failed-json-types.json)。测试脚本恢复数值上精确为整数的传输字段后重跑，两套策略均成功；没有修改生产解析器来容忍错误输入，也没有用失败耗时替代真实决策耗时。

本轮记录对应用户此次性能请求，不创建、扩充或默认执行以后任务的固定回归清单。下阶段的语义改造或更多速度优化尚未执行，范围见[讨论](讨论与优化结论.md)。
