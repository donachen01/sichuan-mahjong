# 独门经营执行与验证

[讨论与结论](讨论与结论.md)

- 生产出牌仲裁对前期副门候选检查实牌，排除参与完整顺子和持有两张及以上的牌。优先规则不会覆盖硬防守，保留向听、风险、路线损失约束。即时进张数和旧综合分无需完全支配原方案。
- 听口比较沿用共享逐张定价及公开供给模型。可胡听张已有剩余墙质量、自摸机会和强制供牌通道。新增仲裁比较总胡牌机会、其中他家供牌的增量、净收益及风险，排除死听；保留末巡结算决策。没有从未见张直接推出墙内张数。
- 中后期沿用按公开状态重算的共享路线。碰后首打继续走实际出牌决策入口，已有碰与过的分支估值，碰后打独门仍属可执行方案。固定牌例通过了碰4筒后打独门的检查。
- 已在单项 C# 测试通过独门保留、副门顺子及对子保护、独门较窄但有供牌的听口、死听及碰后首打等。整套 Smoke 项目有既存的过期 TrySelect 调用导致编译失败，本轮单独编译同一份测试源连接真实 Core。[聚焦测试日志](focused.log)

## Godot 实局配对

使用冻结的当前工作区作为旧版，同一套 Godot 4.6.2 .NET 完整对局入口跑两套 Core。样本从既存牌墙清单固定取数，未按新旧成绩选局。未筛选总体取160副，其中34副有适用座位，分别和两类固定对手各实跑一次。总体以四座等权换算，非适用座位按改动作用域计零，未另实跑。独门组取另一批40副预先识别的独门发牌，每副和两类对手各实跑一次。

共296局。复核两版每对初始发牌、牌墙、定缺、108张牌守恒、签名动作及回放前缀散列，独立重算四座收付。独门组两版均49次胡牌、34次记录到有公开剩余张的独门听口。新版日志有274次前期适用标记，但这批对局里两项新增优先均未接管最终决策。逐对差全部为零，所以本批重抽样区间退化为零，不能估计样本外稀有触发的效果。未得到长期净分提升的证据。
